## Where we are

- **Released:** 0.10.0 = **step 1 of RFC 014 (accounts and sign-in)**: the operator's account and token commands beside a live server, the account's own log, disabling without deleting, the provider's private-issuer allowance, `email_verified`, `PLANETER_SESSION_HOURS`, `PLANETER_LOCAL_PASSWORDS=off`; the gates tooling (tiers, derived limits, snapshot, CI with the pinned prikk); two availability fixes in the running service (IS-74, IS-75); the Japanese read (seventh record, by the architect on the owner's delegation, D-150). Security: `docs/security-review-0.10.0.md`, threat model v0.10 (T-22).
- **Next in order (the architect's, owner's to reorder):** (1) small follow-ups after the release: IS-76 (two key literals in sources), `docs/deliveries.md`'s `sync seal` sentences re-measured on 0.59.0 (PK-88, PK-94), IS-71 (the test suite's cost, with a coverage proof first); (2) **RFC 014 step 2** (a person's own pages: tokens, password, sign-ins, their own log) and **step 3** (provisioning, collaborators); (3) **RFC 013 D-3 by prikk's statements** (Amendment 2), after prikk's release that ships them and its answers to three questions; the floor then moves; (4) RFC 015 (organizations' lifecycle); a private certificate authority for the provider; the periodic check of a person at the provider (open question 7, recommendation: not now).
- **Held and why:** D-3 waits for prikk (no version promised: 0.60.0 at the earliest); **a sign-in with the real sui-id through a running planeter server** has not been measured (the page says so; sui-id's `0.95.0` plan is recorded, ledger ID-13); checks/CI (RFC 006 v2) and issues are separate RFCs; SSH is not planned.
- **Red on `main`:** nothing known (CI green on the tag commit).

## Process lessons (keep — each one cost a bad push or a wrong claim)

- **CI has no prikk.** Integration tests self-skip without it; run the suite locally **with** prikk and
  **once more with prikk shimmed off PATH** before pushing. A review request names both runs.
- **Gate chains use real exit codes.** Edit script → gates → commit chained with `&&`; never pipe a gate
  through `tail`/`echo` inside the chain; one heredoc per statement; edit scripts assert their anchors.
- **Dependency growth is reported before the commit** with `cargo deny` and `cargo audit` results and the
  crate delta ([`dependency-policy.md`](dependency-policy.md)). Manifest edits for measurement are done as
  a visible, separate step.
- **Status lines drift.** The README claimed "no forge code exists yet" through two releases; audit
  README, ROADMAP and this file at every release, not only the CHANGELOG.
- **Tag, publish, release and upstream letters are owner-authorized**, per release, per letter.
