## 2. Plans, in order

Each plan names what it waits on and what it unblocks. Order within a tier is the architect's; order
across tiers is fixed by the dependencies.

1. **Now, during the M2 hold** — in this order (the architect's; each step names its precondition and its
   status as of 2026-10-15):
   1. **T1**, the 0.52.0 re-baseline — **done, reviewed, pushed.**
   2. **T13**, the measurement spike (D-7 granted): **startable now** (prikk 0.52.0 installed; the lock
      update is pushed). Unblocks D-8 and the evidence for RFC 004 v2 and RFC 006 v2. Measurement only.
   3. **Defects and hardening, one small handoff each** (no prikk dependency): **done and reviewed:** IS-22
      (advisories), IS-17 (pins), the floor gate, IS-1 (`--version`), IS-4 (read concurrency). **Assigned:**
      maintenance gates v2 (IS-26: one compiler, a named runner, a release dry run) — **done, approved, pushed**; IS-24 (v2: the auth path
      off the async workers, with constant-work verification, IS-31), IS-16 (raw-content origin), the API contract and cache headers (IS-28, IS-29; D-12) — **IS-24, IS-16 and the API contract are done and approved**; **done and approved (D-13, D-14):** API contract refinements (IS-33) and the MSRV declaration (IS-32). **Not yet assignable:** IS-15 (limits seam: needs
      the spike's A2), IS-25 (fairness: needs measurement), IS-14 (ENF-4 test, *before any write handler*),
      then IS-13, IS-2, IS-7, IS-23 (a mechanical test-module migration).
   4. **Architect, in parallel, no dev time:** RFC 005 v2 and RFC 004 v2 are **drafted** (proposed; not
      acceptable until T13's rows are confirmed); RFC 006 v2 after T13; the requirements note for prikk's
      0.54.0 read-only command design round (the owner conveys it).
   5. **Release 0.3.0** — **released 2026-10-18** (§5; D-11, content amended by D-12 to D-14; one failed tag attempt, D-17).
   Unblocks: a measured two-agent cadence; re-issuable RFCs 004–006; the owner's ruling on M2 (D-8).
2. **When prikk next changes the repository format** (format 8 is unscheduled) — T1 again; T10's first
   real case (what the serving rule and the record mean for repositories already hosted in format 7);
   planeter's input on RFC 158's streaming bound if prikk reopens it. Unblocks: the durability rule.
3. **The write path.** RFC 155 has shipped (whole-repository); **RFC 154 is unscheduled and a keyless delta
   form is not planned.** So the plan is the owner's ruling on M2's shape after the measurement spike
   (theme T13, `rfcs/handoffs/004-transport/transport-measurement-handoff-v1.md` and `rfcs/handoffs/006-ci-runners/ci-read-side-measurement-handoff-v1.md`): RFC 004 handoff v2, then T3, on whole artifacts. **Forge-side branch
   advance (merge) and incremental fetch are what wait for prikk.** Unblocks: T4's review side, T6, T8, T9, T12.
4. **After M2** — T4 (M3) with T5 riding on it (adoption is small once RFC 154 exists), T12's write
   endpoints alongside; T6 as the administration those need. T7's MFA can land in any tier, since it
   waits on nothing — the architect schedules it when a release touching auth is open anyway.
5. **After M3** — T8 (M4) before T9 (M5), recommended: CI gates the review loop; packages have no
   dependents. The owner decides the order (decision point D-4 below).
6. **Before 1.0** — T10 complete, T11 (operations RFC, backup rehearsal, observability), the readiness
   report, then the owner's 1.0 decision.
