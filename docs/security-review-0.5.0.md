# Security review of the 0.5.0 work

| | |
|---|---|
| Document | The security pass the project's rule asks for before a release that adds an inbound flow, a new action and a new binary (RFC 004 "Release implications"). It is a **review by the architect of the design, the code paths and the evidence**, surface by surface — not an external penetration test. It states what each surface defends, the evidence that it does (a test, a mutation, a measurement, a gate), and what remains. |
| Date | 2026-10-30. Basis: threat model v0.6 (`docs/src/planeter-03-threat-model-v0.1.md`: T-15…T-18, INV-10, INV-11, RR-12…RR-18), the reviews of each part, the gates of the release candidate. |
| Verdict | **No open finding blocks 0.5.0.** Findings made on the way were fixed before this review (they are listed at the end); the residual risks are named and accepted in the threat model. |

## How to read the evidence column
*Test* = a test that fails if the control is removed (most have a **mutation** run that proved it); *gate* = a project gate in CI (`cargo deny`, `cargo audit`, ENF-2, `pin-check`, the boundary check); *measured* = a number from a real prikk, in the dependency ledger.

## Surfaces

| Surface | What it defends against | Controls and evidence |
|---|---|---|
| **Propose** (`POST …/transport/propose`) | a hostile or careless member filling the disk, exhausting memory or time, or smuggling work past review; a browser page proposing as the user | bearer token only (the session cookie is removed before authentication; *test*); read gate and `propose` check and the recovery flag and the size are decided **before a byte of the body is read** (*test*: the body's second chunk is never asked for); streamed to disk and hashed, never in memory; quotas that count every retained artifact **and every open intent without a revision** (IS-50; *test*, 16 mutations in the part); a measured memory model, object bound and deadline (*measured*: PK-68, PK-69, PK-75); the write lease; the accept sandboxed with only its own working directories mounted |
| **Accept and recovery** | a killed or stuck write leaving a corrupt or half-recorded repository; recovery itself damaging a repository | an intent is journalled before the accept; a revision is derived only from a complete run, in one transaction (*test*: kill the real server at four points); recovery acts only when its witnesses agree (flag cause, lease table, no foreign process by command line, working directory or open file, `doctor` and `unlock` strictly read), writes each step before taking it, requires a fresh `verify`, never uses prikk's PID advisory, repairs only from an idempotent allow-list and only for an administrator (*test*, 14 mutations); `unlock --force` only for locks that resolve inside the repository's own `.prikk` |
| **Proposals, review, moderation** | stale or forged status; abuse in comments; approval theatre | landing from published history only, received refs shown as sightings (*test*, real prikk); comments immutable in the database (*test* with raw SQL against the triggers); a hidden comment's text leaves through one function (*test*: six callers over JSON, three over HTML, two languages); an approval is bound to its revision and a stale one counts for nothing (*test*); no self-approval; rate limits per person per proposal; Markdown only through the one sanitizer (T-6) |
| **Repository creation** | a hostile archive; a creator tricked into trusting a key; an unfinished repository becoming visible | staged outside every repository and verified in the sandbox; the creator **types each whole key**, never prefilled and never shown back after a mismatch (*test*); `creating` is invisible and unroutable until the last step; any failure or kill removes it whole (*test*: two SIGKILLs of the real server); the start-up sweep deletes only inside the repository root, never through a link, never from an empty store, logging every removal (*test*: planted links); names lowercase, bounded, and reserved from the router's own routes (*test*); prikk bounds nothing of `archive verify/import`, so the edge bound, a measured ceiling and the deadline are the whole protection (*measured*: PK-72) |
| **Everything prikk prints** | an enormous or hostile output exhausting planeter's own memory | a finite cap per prikk verb, child killed on overflow, a named and counted refusal at every caller, never a truncated parse (*test*, 25 mutations, a 1 GiB flood with flat memory; *measured*: PK-74) |
| **The OIDC sign-in path** | forged ID tokens; a vulnerable crypto dependency | `jsonwebtoken` on aws-lc-rs; a 30-row algorithm matrix (valid, tampered payload, tampered signature, wrong key kind, refused HS*/PS*/`none`, wrong audience, expired) that passes on either backend; a test that production code cannot sign (no `EncodingKey`, no `encode(`); `cargo deny` and `cargo audit` exit 0 **with no ignore** (*gate*) |
| **The release chain and the image** | shipping an image that cannot start, or a different image from the one tested; mutable pins | every image is built, **run** (`planeter`, `prikk`, `bwrap`, `prlimit`) and checked against its glibc before anything is pushed or attested, in every mode; after the push the registry's own manifest is read and its config digest must equal the run image's id (*gate*, three rehearsals × two architectures); `pin-check` fails a workflow that pushes or attests without these steps (three mutations of the real workflow); base image pinned by digest; actions pinned by digest |
| **`planeter-client`** (a new binary on users' machines) | a hostile server or network; token theft; being led to trust a wrong key | https only, no `--insecure`; redirects reported and never followed; no cookies; the token in no output (grepped over every output of an end-to-end run); `--cacert` replaces the trust anchors; bounded reads and uploads against a hostile server (*test*); trust typed whole; freshness comparison; no key held and nothing signed (ENF-2 scans the client binary too, *gate*); the server crates may not depend on the client's stack and vice versa (the boundary check, *gate*) |
| **Authorization everywhere** | an unprotected route | every route is registered with an authorization class and the IS-14 table enumerates and probes them (a stranger and a hidden repository get the same 404, byte for byte); `Authorized`, `AuthorizedAny` and `Public(reason)` are the only classes |

## What was not done (said plainly)
* **No external penetration test and no fuzzing campaign.** The inputs that parse hostile bytes (the propose framing, the multipart reader, the archive stage, the have-list, the client's HTTP reader) have planted-case tests and bounded reads, not fuzz corpora. A fuzz target for each is a sensible post-0.5 item.
* **The sandbox is not exercised inside the container image in CI**; the release gate proves the image starts and its tools run. Test your container run options once with a real proposal (RELEASING, "Deploying").
* **aarch64** is built and the image started natively in CI; the server's end-to-end tests run on x86_64 only.
* **The client's three commands run on Linux and macOS**; Windows runs its HTTP/TLS stack, command line, messages and prikk runner (`docs/client.md`).
* **No second factor on accounts** (RR-10) and **in-memory rate limits** that reset on restart (RR-11, RR-13).
* **The Japanese catalog is a draft** and is not shipped. *(Update 2026-10-31, after the tag: the owner reviewed and signed it off, the framework's own error answers were brought into the catalog and the one error shape, and Japanese is on `main` for the next release; no person using assistive technology has tried either language.)*

## Findings made on the way, all closed before this review
IS-44/IS-47 (a label said "verified"/"sealed" without the fact), IS-49 (a count that suggested progress that did not exist), IS-50 (disk accumulated by refused declarations was uncounted), IS-51 (an unreachable, untested repair path), IS-52 (the accept memory model was wrong for large blobs), IS-53 (a landing rule that received history could never meet and that trusted unverified refs), IS-54 (a vulnerable crypto path), IS-55 (uncapped collection of prikk output), IS-56 (an image that could not start), IS-57 (a flaky gate and a misleading "not found").

## Residual risks accepted
RR-12 (an accepted patch cannot be removed), RR-13, RR-14 (the creator's trust decision), RR-15 (reviews are opinion), RR-17 (a C library in the sign-in path), and the open items above. Distribution of the client as release assets is not part of 0.5.0.
