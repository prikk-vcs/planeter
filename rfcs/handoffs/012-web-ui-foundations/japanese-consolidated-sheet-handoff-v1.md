## Change scope

- **T1 — A generator, not a document.** A small tool (`tools/ja-sheet`, std-only or `serde_json` if already in the lock — report which; with tests) that reads **both programs' catalogs** and writes one Markdown sheet. Every row is: key · where it appears (page or situation, from the key's prefix and a maintained table of contexts) · the English · the Japanese draft · placeholders · a note for the reviewer (from a maintained notes table keyed by message; the notes already written in the addenda move into it) · an empty **"reviewer's correction"** column. **A test fails if a row's English or Japanese differs from the catalog, if a catalog key is missing from the sheet, or if the sheet names a key the catalog does not have** (the sheet cannot drift). The sheet is regenerated by one command and carries the commit hash and the date in its header.
- **T2 — Order and groups (the reviewer may stop after any group; each group says what it covers and how many rows).**
  **A. The words that carry trust (≈ 15 rows):** the badges and their explanations (`assurance.*`, `explain.*`), the review line and decision words (`review.word.*`, `review.means.*`, `decision.form.*`), the states of a proposal (`proposal.state.*`, `proposal.what.*`), the key-trust screens of repository creation (`stage.key.*`, `stage.none.*`, `created.unverified`), the landed/held/unknown sentences. **B. The pages a person reads, page by page** (home, repository, files, history, refs, verification, sign-in, proposals list and detail, comments, creating a repository, the 404 and error pages), in the order a person meets them. **C. The command-line program** (`planeter-client`: its help, sentences and refusals). **D. Developer- and operator-facing texts (`error.*`, `quota.*`, `recovery.*`, ≈ 180 rows):** API error messages and hints, quota refusals, recovery plan sentences. Group D is **marked optional for the sign-off**: see T3.
  Within a group, rows keep catalog order. The sheet's first page says, in Japanese and English, what to do (write a corrected text in the last column, or "OK"; leave a row empty to accept it), what the hard terms are (the glossary's list, with the draft's choice and the alternatives, each as one row to decide first), and what happens next.
- **T3 — Group D can stay English, if the owner decides so; the mechanism is built either way.** Add (do not yet turn on) a catalog mechanism "English in every language" for a named list of keys: such a key is looked up in the English table whatever the caller's language, the Japanese table does not hold it, and the tests that require the same keys in both catalogs allow exactly that list (a test fails if the list names a key the English catalog lacks, or if a listed key also appears in the Japanese table). The list is a constant `ENGLISH_ONLY_KEYS` in `catalog/mod.rs`, **empty by default**; turning group D off is then a one-line change by the architect after the owner says so, and the sheet's group D disappears. Tests: with a planted list, a Japanese caller gets the English text for those keys and Japanese for the rest; the API's `Accept-Language` path and the pages behave the same; the pseudo-language still wraps every message.
- **T4 — Retire the addenda from the reviewer's path.** The old sheet and its addenda are moved to `.git-exclude/review-requests/japanese-review-sheet-superseded/` (not deleted), with a README line saying the generated sheet replaces them; corrections the owner or the colleague had already written into them (if any) are listed in the report and carried over by hand into the generator's notes or the catalog, with a line each. The next feature that adds a Japanese message regenerates the sheet; nobody writes an addendum again.
- **T5 — The integration path, so the sign-off is a short step when it comes.** Document in `docs/messages-and-languages.md`: how corrections in the sheet become catalog and glossary edits (one commit per group), what `JA_REVIEWED`/`JA_SIGNOFF` record (who, when, which sheet hash), what "phase 2" still contains (hide the lone English switcher button when only English is offered; finalize the accessibility statement's Japanese wording), and that the first page of the generated sheet lists these steps.

## Non-change scope

No Japanese text changes (the sheet shows the current draft as it is); no English change; `JA_REVIEWED` stays false; no new message; no version or release change.

## Acceptance criteria

The generator and its drift tests; one generated sheet containing every message of both catalogs exactly once, grouped as T2 says, with the counts per group in its header and the first-page instructions in both languages; the `ENGLISH_ONLY_KEYS` mechanism with its tests and an empty list; the old files moved with their README; the documentation; all earlier checks pass; every gate green (fmt, floor, pin, clippy, both test runs named, deny and audit 0, ENF-2, doc), CI green.

## Prohibited shortcuts

No hand-edited sheet; no row whose text is not the catalog's; no silent omission of a message; no change of a trust label; no turning group D off.

## Required evidence and review-request format

Commits (hash → what, by task); the generated sheet's path and its header (counts per group, commit hash); the drift test's planted failures; the carried-over corrections list; every gate with command and exit code and the advisory-database HEAD; deviations and open questions.
