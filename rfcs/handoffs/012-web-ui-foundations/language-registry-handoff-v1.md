## What is already general (keep) and what is Japanese-shaped (change)

**Already general:** `LangDef` (tag, endonym, direction, plural function, separators, entries), negotiation with q-values and the cookie, `<html lang dir>` and `Vary`, the completeness audit (same keys, same placeholders), the `ENGLISH_ONLY_KEYS` mechanism, the pseudo-language that proves right-to-left wrapping.
**Japanese-shaped:** (1) `JA_REVIEWED` / `JA_SIGNOFF` constants and a hard-coded `shipped()` array; (2) `Plural` has only `One` and `Other` — enough for English and Japanese, **wrong for Russian, Polish, Arabic, Welsh, Czech…** (CLDR categories: zero, one, two, few, many, other); (3) matching by **primary subtag only** — `zh-Hant`/`zh-Hans` and `pt-BR`/`pt-PT` cannot be told apart; (4) the footer switcher is one button per language — it does not scale past three or four; (5) the client has its own `Lang` enum and its own copy of the sign-off flag; (6) the review-sheet tool, the consistency tests, the retired/forbidden term lists and the glossary's Japanese section are Japanese-only, with the language's rules written into Rust; (7) a sign-off is recorded once for a catalog and says nothing about messages written afterwards.

## Phase 1 — the registry (one change set, behaviour unchanged for en and ja)

- **T1 — A shared crate `planeter-i18n`** (no external dependency; `forbid(unsafe_code)`; added to `tools/boundary-check`'s allowed edges: the server crates and the client may depend on it, it depends on neither). It holds `LangDef`, `Plural` categories, the registry type, negotiation, the sign-off record type and the audit functions; the server's `catalog/mod.rs` and the client's `catalog.rs` keep only their own message tables and key enums. One implementation of negotiation and plurals instead of two.
- **T2 — One registry; sign-off is data on the language.** `LANGUAGES: &[&LangDef]` is the only list. `LangDef` gains `status: Status` = `Source` (English) | `Draft` | `SignedOff(SignOff)`, and `SignOff { reviewers: &[&str] (names or roles, at least one), date, commit, sheet_fingerprint, note: &str }`. `shipped()` = `Source` + `SignedOff`; `previewable()` = `Draft`. **`JA_REVIEWED` and `JA_SIGNOFF` disappear**; Japanese's record becomes its `SignOff` (reviewer: the owner; the date, commit and fingerprint exactly as recorded today, and the note keeps the sentence about the eight messages and the Japanese accessibility section that the owner had not read). One test, **over every language in the registry**, fails a `SignedOff` without a reviewer, a date, a 16-hex fingerprint and a commit, and a `Draft` that is offered without the preview setting. Both programs read the same registry type.
- **T3 — Plural categories.** `Plural` becomes the CLDR set (`Zero, One, Two, Few, Many, Other`); each `LangDef` lists the categories it uses and has a `plural(n) -> Category` function; an `Entry` holds a form per category the language uses (`other` required). English and Japanese keep their one/other and other-only rules (their tables do not change in meaning). Add the plural functions of **Russian, Polish, Arabic and Welsh as tested rule functions with no catalogs** (CLDR test vectors for 0, 1, 2, 3, 5, 11, 21, 100, 101, 1000000 and fractions are not needed: counts are integers) so the machinery is proven before the first real language; the audit checks that an entry has exactly the forms its language declares and that each form contains `{count}`. No new dependency (hand-written rules with test vectors; revisit a library when five or more languages ship).
- **T4 — Negotiation by BCP 47, not by first subtag.** `LangDef.tag` is a full tag (`en`, `ja`, `zh-Hant`, `pt-BR`); matching order: exact (case-insensitive) → same language and script → same language (the first registered) → English. `Accept-Language` q-values and the cookie follow the same function. Tests with `zh-TW` → `zh-Hant`, `zh-CN` → `zh-Hans`, `pt-PT` when only `pt-BR` ships, `ja-JP`, `en-GB`, `fr` → English, `*` and `q=0` handled as today. The client's choice from `LC_ALL`/`LC_MESSAGES`/`LANG` uses the same function (`de_DE.UTF-8`, `zh_TW.Big5`, `C`, `POSIX`).
- **T5 — A switcher that scales.** Up to three languages: inline buttons as today. Four or more: one `<details>` "Language" listing the endonyms, each entry still a no-script form with `lang` and `hreflang`-style attributes, the current one marked, keyboard order and names unchanged for assistive technology; the structural checker and plain-words tests run for both renderings (register a fourth test language to prove it, as `register_test_language` does today).
- **T6 — The client uses the registry.** `enum Lang` is replaced by the shared handle; the client's own sign-off flag is gone; `--lang` accepts any shipped tag (error text lists them); the help names the shipped languages from the registry, not from a literal "en|ja".

## Phase 2 — tooling and tests that do not name a language

- **T7 — One review-sheet tool for any language: `planeter-i18n-sheet`** (rename of `ja-sheet`, history kept). `--lang <tag>` writes the sheet for that language (English column, the language's column, the same groups); the first page's instructions come from a per-language file `tools/i18n-sheet/data/<tag>/instructions` (English plus the language itself, written by whoever adds the language; the Japanese text moves there), the hard-terms table from `docs/glossary/<tag>.md`, the notes from `data/<tag>/notes.tsv`; contexts stay shared. The "(a draft)" wording on the first page becomes status-aware ("draft" for `Draft`, "current text" for `SignedOff`).
- **T8 — A baseline of what was signed.** For every `SignedOff` language, a committed file `crates/*/locales/<tag>.signed` lists `key<TAB>hash` of each message **as signed off**. The sheet marks every row as `unchanged`, `changed since sign-off` or `new since sign-off`; the header counts them; `--check` reports the counts and exits 0 (it is information, not a failure). The registry exposes `unreviewed_count(tag)`; the server logs it once at start ("ja: 8 messages newer than the sign-off"), the accessibility statement's language bullet is generated from the same fact in the release step, and the release checklist (RELEASING) says to list the count in the notes. **Japanese's baseline is the signed-off sheet (fingerprint `54ebae05ad914ab6`, commit `f54ae38`) minus the eight edge messages and the sections the owner has not read** — those therefore show as "new since sign-off" until the owner reads them, which is the truth. Policy, stated in `docs/messages-and-languages.md`: a message written after a sign-off ships in that language (the dev team writes it, the glossary rules apply) **and is flagged until a reviewer has read it**; nothing is silently counted as reviewed.
- **T9 — Tests over the registry, rules as data.** `ja_catalog`, `ja_consistency`, `glossary_ja`, `ja_offered`, the Japanese retired/forbidden lists become tests that **iterate over every language in the registry** and read their rules from `crates/planeter-web/tests/i18n/<tag>.rules` (one line per rule: kind · pattern · reason; kinds: `forbidden`, `required-pair`, `style` for the full-width/half-width and number-spacing conventions, each with a planted both-ways example in the same file); the Japanese rules move there unchanged (the 25-correction rules and their planted cases included). English's retired words become `en.rules`. A new language without a rules file fails the build with a sentence that says to add one (an empty file is allowed and says so). `docs/glossary.md` §5 splits into `docs/glossary/<tag>.md` (the English concept table stays in `docs/glossary.md`); `glossary_*` tests read the language files.
- **T10 — The process, written.** `docs/messages-and-languages.md` gets "Adding a language" as a checklist the next contributor can follow without the architect: the tag; the `LangDef` (endonym, direction, plural categories — with the CLDR reference —, separators); the catalog; the rules file; the glossary file; the sheet instructions; draft → preview → sheet → named reviewers (at least one fluent reader, recorded by name or role) → `SignOff`; what a right-to-left language additionally needs (the logical-property checks already exist; a **real** right-to-left page must be read by a fluent reader before shipping — the accessibility statement says today that none has been); who may propose a translation (any person, as a proposal to this project; the sign-off is the maintainers'); and the policy of T8.
- **T11 — The RFC.** Add to RFC 012 a short "Amendment (2026-11-04)" under D-3 pointing to this handoff: the registry, sign-off as data, CLDR plural categories, BCP 47 matching, the switcher rule, shared tooling, the baseline policy (the architect has written the amendment; the dev team references it in the docs).

## Phase 3 (not assigned — for the architect's later decision, after phases 1–2 are reviewed)
**Translator-friendly catalogs.** Today a message table is Rust source (`msg("key", "text")`): a translator who is not a Rust developer cannot contribute without help. A plain-text catalog format (one file per language, keys and forms in a line-based syntax, parsed at build time by a small hand-written parser, embedded with `include_str!`, no new dependency, the same audit and the same sheet) would remove that barrier. It changes how every message is stored, so it is its own decision with its own measurement; it is recorded here so that phases 1–2 do not make it harder (the registry refers to a language's entries through one function).

## Non-change scope
No English or Japanese text changes; no new language is added (the four test plural rules have no catalogs); no change to the API's error shape, to the stylesheet or the templates beyond T5; no change of dates (ISO 8601 UTC in every language) or of the units; `ENGLISH_ONLY_KEYS` stays empty; no external dependency; no `unsafe`; no version or release change.

## Acceptance criteria
T1–T11 as written, with: the registry as the only language list (a grep finds no `JA_`/`Ja` outside Japanese data and the Japanese catalog); the same output for English and Japanese before and after (the regenerated Japanese sheet differs from the delivered one only in the new status column and the first-page wording of T7; the catalog fingerprint is unchanged); tests of the four plural functions and of a fourth registered language through the switcher, negotiation and the audit; the baseline file for Japanese and the counts it produces; all earlier checks pass; every gate green (fmt, floor, pin, clippy, both test runs named, deny and audit 0, ENF-2 on both binaries, doc, the boundary check with its new edge), CI green on three systems.

## Prohibited shortcuts
No language-named constant or function left in shared code; no weakening of a Japanese rule while moving it (the planted cases move with it); no silent counting of an unread message as reviewed; no plural rule without test vectors; no external dependency.

## Required evidence and review-request format
Commits (hash → what, by task); before/after of the registry and of `shipped()`; the Japanese `SignOff` as data next to the old constants; the plural test vectors; the negotiation table; screenshots-as-HTML of the switcher with two and with four languages (checker result); the regenerated sheet's header with the new counts; the grep for `JA_`/`Ja`; every gate with command and exit code and the advisory-database HEAD; deviations and open questions.
