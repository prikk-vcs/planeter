## Change scope
**T1 — the command.** `planeter-client deliver <https://host/owner/name> [--repo DIR] [--yes] [--dry-run] [--token-file FILE] [--cacert FILE] [--lang …] [--verbose]` (the common options as the other commands have them; `--repo` names the maintainer's repository, default the current directory). The steps, each with its own sentence in both languages:
1. **Local checks before anything is sent:** the directory is a prikk repository; it has a local `heads/main`; `prikk` is at the floor (the existing check); the maintainer's repository has no unfinished work that makes `archive export` refuse (say what prikk says, verbatim in `--verbose`).
2. **Export:** `prikk archive export` of the whole repository into a private temporary file (mode 0600, in the state/temp directory the client already uses, removed on every exit path including a kill: say how), with a progress line like propose's ("Exporting your repository…" with the size). The size is checked against the server's advertised bound **if the server states it** (it does not today: do not invent a request; the server's 413 is the answer and is said in words with the number in the response's hint).
3. **Upload:** the same framing as repository creation's import (`PLANETER-IMPORT-1`, the metadata `{}`, the archive), with the bearer token only (token from the environment or a private file, as propose), https only, redirects reported and never followed, bounded reads of the answer, the same retry policy as propose (none for a refused answer; a network failure is exit 3 and says whether anything may have been received: the server journals, so a re-run is safe).
4. **The report.** Print the delivery's `message` (the server's words, in the caller's language, **including the owner's sentence** "Delivering replaces this repository's branch {ref} with yours. It is accepted only if yours continues from the current one; nothing is signed by this server." when the report is acceptable), then, in the client's own words from the report's fields: the old and new tip (the first 12 characters), "{n} new blocks" is **not** said (a reader does not know *blocks*): say "{n} new commits" only if the glossary term fits; otherwise "{n} new changes"; use the project's glossary and report which you chose, the branches added, "{k} open proposals stay", "{k} will land: #…", and "{k} cannot be kept (their files were removed): #…" with the titles escaped as the other commands escape server text (control characters shown visibly). A **refused** report prints the server's `message` and `hint` (the reason and what to do) and exits **1** ("the server refused"); `--dry-run` stops here for an acceptable one too (it has cancelled the delivery: `DELETE`, and says so).
5. **Confirm.** Ask "Deliver it? [y/N]" on the terminal (no default yes; a non-terminal needs `--yes`, as clone's `--trust-key` rule), then `POST …/confirm`. Show the `done` message, or poll `GET …/deliveries/{id}` every 2 s (to a limit of 15 minutes, a visible "still working" line every 30 s) when the answer is `202`; a `failed` delivery prints its failure message/hint and exits 1; **`needs_recovery: true`** says plainly that the server must finish it and what the person does (wait; tell the person who runs the server) and exits 1; a Ctrl-C while waiting says the delivery continues on the server and prints the id and how to look (`GET`), exit 130 as the other commands.
6. **Exit codes** as the README/`help.main` table of the client (0 done, 1 the server refused, 2 command line, 3 network/TLS, 4 your prikk failed, 5 local files or keys): reuse, do not add one.
7. **A `403`** on any of the three calls prints a sentence that says what the 403 means here (RFC 008 D-9, API deviation 1): "Delivering needs a token with full access to this repository, from a maintainer. This token cannot deliver." (the Japanese by you), with the server's hint under `--verbose`. A `404` is the one existence-neutral sentence the client already uses.
8. **A repository that already follows the forge:** nothing special; the rule is the server's. If the server answers `nothing_to_deliver` the command exits **0** with the server's sentence ("Nothing to deliver: …").
**T2 — what happens after `fetch` and `clone` (RFC D-10).** (a) After a `fetch` that landed the forge's `heads/main` as a **received copy that is newer than the person's own `heads/main`** (the client sees both tips: it already prints "N branches and tags came as received copies"), add one sentence in both languages: "The project's branch moved on the server. A fresh clone has it exactly; to follow it in this clone, merge it yourself with prikk (this makes your own commit, not the server's)." — only when the received tip differs from the person's `heads/main`; never when nothing moved. (b) `docs/client.md`: a section "When the project's branch moves" with the same facts (a fresh clone is exact; `fetch` lands a received copy and never touches your branches; `merge --from` makes your own block, measured in PK-83/PK-84). (c) `clone` right after a delivery needs no change (the measurement: heads/main is the delivered tip and there is no `remotes/` copy).
**T3 — IS-62.** The freshness record is keyed by **the clone's directory** (its canonical absolute path) **and** the repository address: a second clone of one repository on one machine fetches its own state. Migration: an existing record keyed by address alone is read as the record of the clone directory that wrote it **only if** that directory is the one being fetched into; otherwise it is ignored (a fetch then does a full fetch, which is always safe). Tests: two clones of one repository (the measurement's `r5c` case): the second clone's first `fetch` after the first clone fetched fetches (not "Nothing changed"); a moved/renamed clone directory does a full fetch; the old-format record file is still readable and never makes a fetch skip what it should not.
**T4 — messages (English written by you; the Japanese plain, by you, flagged for the owner; no 保持 or 預かる; the glossary's 引き渡す / 引き渡し for deliver).** Every new sentence of the command, the help (`help.main` and a new `help.deliver`, with an example), the exit codes table (unchanged numbers), usage errors, the after-fetch sentence. A scan as the delivery API's: none of *stage, chain, tip, adopt, received (except the after-fetch sentence, which uses "received copy" because that is what the client has always called it: keep that one), claim, seal, block* in a sentence of `deliver`.

## Tests (each hostile or lifecycle case with a **mutation** shown failing once)
- **Mock server** (`flows.rs`): the whole road (upload → acceptable report → prompt → confirm → done); a refused report for each closed reason prints the server's message and hint and exits 1; `--dry-run` cancels (`DELETE` seen) and exits 0; a non-terminal without `--yes` refuses before the confirm (no `POST …/confirm` seen); `202` polled to `done`; `failed` and `needs_recovery`; `403` (the sentence), `404`, `413` (in words), `409 delivery_busy`; a redirect is reported not followed; the token is in no output (the existing grep over every output); the temporary archive is gone after success, refusal, failure and a kill (SIGKILL the client at the upload: the next run finds no stale file or cleans it); plain `http://` refused as everywhere; control characters in titles shown visibly.
- **Real server** (`crates/planeter/tests/client_e2e.rs` or a new file next to it, real client → real server behind TLS → real prikk 0.58.0): a maintainer with a `full` token delivers the measurement's scenario (P1 lands, P2 stays, P3 partly lands): the printed report matches the API's; confirm; afterwards a **fresh clone** has `heads/main` = the delivered tip and the working tree; a contributor proposes on top of it with the real client (`propose`) and it is accepted on the delivered base; `deliver` of the same repository again prints "Nothing to deliver" and exits 0; **an older archive** (rollback) and **a divergent one** and **one signed by an unadopted key** are refused with the right sentences and exit 1, the forge's `heads/main` unchanged; a `write` token gets the 403 sentence; a token for another repository gets the 404 sentence.
- **IS-62:** the two-clone test above through the real client and server.
- **After fetch:** the sentence appears after a delivery moved the branch (an older clone), and does not appear when nothing moved (both languages).
- **Real-prikk tests skip with a reason when prikk or bubblewrap is absent; stand-in prikk tests run `Sandbox::Unconfined`** (the CI runner has neither: say you ran the new tests once with `bwrap`, `prikk` and `prlimit` removed from `PATH`).
- **ENF-2:** the client's binary is scanned as before; the `deliver` module contains no call of `seal`, `merge`, `branch close`, `--allow-non-fast-forward`, `--yes` to prikk (a source scan test, as the engine's).
- The client's stress target (`PLANETER_STRESS_RUNS=20`) is run once at the end (the client changed).

## Non-change scope
No server change (a defect found there is reported, not fixed); no change to `clone` or `propose` behaviour except IS-62's record and the after-fetch sentence; no new dependency; no `unsafe`; no version, no CHANGELOG entry (the release candidate); no sign-off data.

## Acceptance criteria
T1–T4 with every test and mutation; the real-server scenario through the real client; IS-62 closed by the two-clone test; every new message in both languages, scanned; the sheet regenerated and `--check`ed (report the count to read: the 62 of the API plus the new ones); all gates green (fmt, floor, pin, clippy, tests with prikk 0.58.0 and without prikk, deny/audit 0 with the pinned tools, ENF-2, doc, msrv; the dry run is not expected to pass at the released version 0.7.0: D-82); CI green on all three systems of the `client` job.

Commits (hash → what); the full output of a real `deliver` (acceptable, refused for each reason, dry run, done, 403, 404) in both languages, saved as files; the message table (key → English → 日本語); the IS-62 before/after; the tests and mutations; the stress run; the sheet header and fingerprint; every gate with command, exit code, tool versions and the advisory-database HEAD; deviations and open questions.
