## Change scope
**T1 — Storage (`planeter-store`).** A `deliveries` table behind a trait with an in-memory and a SQLite implementation (the pattern of `change.rs`; idempotent `CREATE TABLE IF NOT EXISTS`; no change to any existing table): `delivery_id`, `repo_id`, `principal`, `state` ∈ {`staged`, `reported`, `confirmed`, `exchanged`, `reaccepting`, `done`, `failed`, `abandoned`, `expired`}, `archive_digest`, `archive_bytes`, `stage_dir` (a name, not a path outside the stage root), `old_tip`, `new_tip` (block ids), `report_json` (the closed report of RFC D-5, below), `reason` (the closed refusal reason when `failed`), `created_at`, `updated_at`, `finished_at`. **At most one delivery per repository in a non-final state** (a unique partial index or an equivalent check inside the transaction; a second `start` answers `busy`). Transitions are one function that refuses an illegal one. The record of the last `done` delivery of a repository (who, when, old and new tip, counts) is readable (for the repository page).
**T2 — Stage and rule (`planeter-transport::delivery`, new module).** `DeliveryService::start(principal, repo, archive upload)` and `report(delivery_id)`:
1. **Upload and admission** through the same machinery as creation's stage (`StageUpload`, the size bound `PLANETER_IMPORT_MAX_MB` default 100 MiB, the stage budget per principal and the stage lifetime of 24 h, the heavy-pool admission at the creation cost model: `verify_cost`, `import_cost`, ceilings). Refusals keep creation's closed reasons and words where they apply (`too_large`, `stage_limit`).
2. **The stage repository:** a fresh scratch repository inside the delivery's own directory on the **repositories' own filesystem** (the exchange in T3 needs it; check at start and refuse with `unavailable` and a log line if not), `init`, then `trust maintainer add` for **every key of the live repository's `trust_list`** (read from the live repository by the driver; never from the archive) — then `archive verify`, then `archive import --adopt --format json`, then `branch --format json --all`, `verify --format json`, `log --ref <each local ref> --format json` with a limit of **at least the chain length of the staged ref (count blocks first; never a fixed 5000 that a longer history would silently exceed: if the length cannot be bounded, refuse with `damaged_archive`)**. Every prikk call is sandboxed with the cost model's ceilings (as creation does); a killed call is never resumed: the stage is discarded and the delivery fails `failed`.
3. **The rule (RFC D-3), as one pure function** `decide(live: LiveFacts, staged: StagedFacts) -> Result<Acceptable, Refusal>` over typed facts both read by the driver readers, with the five checks in the RFC's order and the closed reasons `no_main`, `unadopted_key`, `not_a_successor` (a live ref whose tip is not in the staged chain: older, diverged; the report says which the facts show, `older_or_diverged` is one reason; a history sharing **no** block is `unrelated`), `branch_missing`, `nothing_to_deliver`, `damaged_archive` (prikk refused the archive: its words are logged, the reason is the closed one). `LiveFacts` = every published ref and its tip block id (from the live `branch --format json --all` and `log`), the trust list, the proposals. The pure function has its own unit tests for every combination of the `r12.json` table (copy those cases as data).
4. **The report (RFC D-5)** is a typed struct, serialized once and stored: `acceptable | refused(reason)`, `old_tip`, `new_tip`, `new_blocks` (count of staged-chain blocks after the live tip), `refs_added`, `proposals_stay` (open proposals, ids), `proposals_land` (open proposals whose **every patch** is in a block of the staged `heads/main` chain), `proposals_cannot_be_kept` (open proposals with a revision whose retained artifact is gone: the artifact store tells; D-8), `trusted_keys` (key ids and fingerprints of the live trust list), `archive_bytes`. Landing is evaluated with the existing observation's own function on the staged repository's `log` (do not write a second definition of landed: reuse `proposals.rs` with the followed ref **`heads/main`** as a parameter).
**T3 — Install (`confirm`, RFC D-7).** `DeliveryService::confirm(principal, delivery_id)` — only for a `reported` + `acceptable` delivery by the same principal that started it, within its lifetime:
1. Take the repository's **W lease** (with a deadline: `PLANETER_CREATE_DEADLINE_SECS`'s existing machinery or a sibling constant, stated in the report; a confirm that cannot get the lease in time answers `busy` and leaves the delivery `reported`).
2. **Re-check under the lease** that the live repository's tip is still the report's `old_tip` and the rule still holds against it (re-run `decide` with fresh live facts and the stored staged facts); otherwise the delivery becomes `failed` with the reason and **nothing is touched**.
3. Write the **intent** (state `confirmed`) — durable before anything moves.
4. **Exchange** the stage directory and the live repository directory with `renameat2(..., RENAME_EXCHANGE)` (use `rustix` or `nix` **only if it is already in the lock; otherwise a three-line `libc` call behind one function in the one module that may use it, or — if that needs `unsafe` — stop and ask: the workspace is `forbid(unsafe_code)`; the fallback allowed without asking is two ordinary renames with the 503 window the measurement showed, stated in the module docs and counted). State `exchanged`.
5. **Bump the revision counter** (`write_completed`) so the fingerprint does not rest on file times.
6. State `reaccepting`; for **every open proposal, every revision in order**, **accept the retained artifact** with the same driver call and the same bounds `propose.rs` uses for an accept (admission class, ceilings, deadline — each re-accept is one ordinary accept); a revision whose artifact is gone is skipped and counted (it was listed in the report); a re-accept that fails stops the sequence and leaves the delivery `reaccepting` with the repository flagged `needs-recovery` (reason `delivery_unfinished`) — **never** rolled back.
7. `verify` the new repository (must be ok; `publication-trust` anywhere is a failure → `failed`, flagged, loud), state `done`, **remove the previous generation and the stage** (the delivered history contains the old one; nothing irreplaceable is deleted: the open proposals' state is re-created), release the lease, drop the export cache entry for the repository (the existing way), and let the landing observation re-read once (the fingerprint moved).
**T4 — Recovery.** `reconcile_at_start` (and the recovery procedure's witness model) learn the delivery states: `staged`/`reported`/`failed`/`expired`: discard the stage (a sweep for stale stages, as creation's `sweep_stages`); `confirmed` with **no** exchange having happened (the live directory is still the old repository: check by the stage directory's presence and the live tip): abandon, discard the stage; `exchanged` or `reaccepting`: **complete** from the intent (the exchange is done; re-accept every artifact again — idempotent: a claim already accepted is "new objects: 0" — then verify and finish). A killed prikk call's stale locks (`active.lock`, `objects.lock`; PK-84) are cleared with `unlock --lock <path> --force` after the existing witnesses agree (reuse `recovery.rs`; do **not** pass `--yes`). A kill at **every step** is a test (below).
**T5 — Landing restricted to the followed branch (RFC D-6).** `proposals.rs`: the observation counts only blocks of `heads/main` (a constant `FOLLOWED_REF` in one place, referenced by T2's report); a proposal in an extra published branch does not land. Update the existing tests that assumed any published ref; add one for the extra branch.

## Tests (real prikk 0.57.0 where it matters; fixtures from the measurement; each hostile case with a **mutation** shown failing once)
- **The rule, pure:** the whole `r12.json` table in both forge states (S0, S1) as data, plus: an extra branch accepted; a deleted branch refused (`branch_missing`); the same tip (`nothing_to_deliver`); a staged chain longer than any fixed limit (a 6,000-block history: no false `not_a_successor`); mutation: the chain test replaced by "the staged tip is local" → older/diverged/unrelated fail.
- **The stage, real prikk:** every archive of the measurement (D1, D2, `x`, `mix`, `xcarry`, `dev`, `older`, `div`, `m2`, `m2div`, `unrelated`, truncated, five flips) through `start` → report: the closed reasons, the words logged, **the live repository's `.prikk` tree hash byte-identical after every refusal**; mutation: the stage trusts the archive's carried keys → `xcarry`/`x` tests fail; mutation: trust list taken from the archive.
- **The install, real prikk and the real transport:** the scenario of the measurement (P1 lands, P2 stays, P3 partly lands) end to end through `start → report → confirm`: the report's lists are right; afterwards `heads/main` = the delivered tip, no `remotes/`, `sync pending` = the open proposals' patches, P1 `landed`, P2/P3 open with the right counts, claim ids unchanged, the fingerprint moved, the previous generation and the stage are gone; a **second delivery** (D2) the same; a delivery that lands nothing new for a proposal; a proposal whose artifact was removed (listed, kept readable, not re-created); a 1,000-patch revision re-accepted (time reported, no new assertion on time).
- **Crash points:** SIGKILL of the **server process** (the transport test harness's way: a child) at each of: during the stage import; after the report; after the intent; **before** the exchange; **after** the exchange; during the first, a middle and the last re-accept; before `done`; after each, **restart the server** and assert the repository ends in the new state with every open proposal intact (or, for kills before the exchange, in the old state with the stage discarded), `verify` ok, `doctor` with no error, no delivery left non-final, no stale lock, no flag; mutation: the intent is written after the exchange → the "after the exchange" kill test fails; mutation: `reconcile_at_start` ignores `exchanged` → fails.
- **Concurrency:** a second `start` while one is in flight (`busy`); a delivery while an accept is running (the accept finishes, the confirm waits for the lease or answers `busy`, never both write); an accept while a confirm holds the lease (it waits or is refused as the lease says); two confirms of one delivery (one wins, the other is told it is done).
- **Authorization is not here** (handoff 2), but the engine functions take the principal and the repository record, never a bare path.
- **No server-side signing:** ENF-2 still passes; `grep` shows no `--allow-non-fast-forward`, no `branch close`, no `merge`/`seal` call in the module (a test over the module's source is acceptable, as the `--yes` guard is).
- **Logs and counters:** one counter per outcome (`accepted_reports`, each refusal reason, `confirmed`, `done`, `failed`, `abandoned`, `recovered`) in the metrics style of `Metrics::changes`; no file or branch name, key or content in any log line (a canary test as for the changes view).

## Non-change scope
No route, no page, no client, no catalog text (handoff 2), no setting except what the existing `PLANETER_IMPORT_MAX_MB` / `PLANETER_STAGE_BUDGET_MB` / deadline already are (state in the report if a new constant is needed: it is a constant, not a setting), no policy table, no new dependency (if `renameat2` forces one, stop and ask with the measurement per dependency policy rule 1), no `unsafe`, no change to `Failure`/`classify_failure` of accept, no version, no floor.

## Acceptance criteria
T1–T5 with every test and mutation; the measurement's scenario reproduced through the engine; every refusal leaves the live tree byte-identical; every kill point converges; all gates green (fmt, floor, pin, clippy, tests with prikk 0.57.0 and without — the real-prikk tests skip with a reason — `cargo deny`/`cargo audit` 0 with the pinned tools, ENF-2, doc, msrv, the dry run with a fresh target); CI green. The threat-model input (half a page: what the engine accepts, costs, refuses, never does) in the review request.

## Required evidence and review-request format
Commits (hash → what, storage first); the closed list of reasons and states; the table of tests (case → mutation → result); the kill-point table (point → state after the kill → state after restart); timings of a small and a 63 MiB delivery end to end and of the re-accepts; the lease window; how the exchange was done (and whether `unsafe` or a dependency was avoided); every gate with command, exit code, tool versions and the advisory-database HEAD; deviations and open questions.
