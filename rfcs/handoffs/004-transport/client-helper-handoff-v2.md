# RFC 004 — Transport — Implementation Handoff (v2, part 9): the client helper, `planeter-client`

| | |
|---|---|
| Document | RFC 004 D-10: a person with their own prikk and their own keys can **clone** a repository from a forge, **fetch** its newer state, and **propose** their work to it — in plain words, with the next step stated, never pretending that a proposal moved a branch. The helper drives the user's own prikk and holds no key. Decisions made for this handoff (D-50, by the owner's delegation): the HTTP/TLS stack is `ureq` 3 + `rustls` with the **`aws-lc-rs`** provider + **compiled-in `webpki-roots`**, https only; the licence `CDLA-Permissive-2.0` (the Mozilla root list's data licence) is allowed **for the `webpki-roots` crate only** (a per-crate exception in `deny.toml`, not a global allow); the binary is **`planeter-client`** (the server is `planeter`). |

## T0 — Gate: the dependency set builds on all three systems (its own commit and CI job)

New crate `crates/planeter-client` (binary `planeter-client`; `#![forbid(unsafe_code)]`; its own `rust-version` 1.88.0). Dependencies: `ureq` 3 (default features off, `rustls` with the `aws-lc-rs` provider, `webpki-roots`; **no** cookies, gzip, json or `platform-verifier`), `serde`/`serde_json`, and nothing else without a rule-1 report. **The server crates must not gain any of these** (check with the boundary check; `cargo tree -p planeter` unchanged). `deny.toml`: a **per-crate** `[[licenses.exceptions]]` for `webpki-roots` (and `webpki-root-certs` if it enters) allowing only `CDLA-Permissive-2.0`, with a comment citing D-50; no global allow. Report per rule 1: "N → M crates (+K); deny: …; audit: …; new licences: …" on the fresh database.
**CI:** a job building `planeter-client` (release, `--locked`) on `ubuntu-24.04`, `macos-latest` pinned to a fixed label, and `windows-2025` (pinned labels, as `pin-check` requires), plus `cargo test -p planeter-client`. If Windows needs `nasm`/`cmake`/`perl` beyond the runner's defaults, **install it in the job and document it as a Windows build requirement**; if aws-lc cannot be built there at all, stop and report with the error (the architect then decides on a provider for that target). Native build requirements are measured, not assumed: report them per OS. A binary-size and build-time line per OS.

## T1 — The HTTP core (no commands yet)

Module `http`: (a) `get_to_file(url, dest, etag?, resume?)` streaming to `dest.partial` and renaming on completion, `Range` + `If-Range` resume, `If-None-Match` → `NotModified`, size and idle/total timeouts, **no body held in memory**; (b) `post_framed(url, prefix_bytes, file, token)` with an exact `Content-Length`, streamed; (c) bearer token from `PLANETER_TOKEN` or `--token-file` (the file must not be group/world-readable on Unix, else refused with the sentence saying so; never a command-line argument, never in any log, error or `--verbose` output — a test greps all outputs for the token); (d) redirects **refused** (a redirect is reported as such, never followed), cookies none, `HTTPS_PROXY`/`NO_PROXY` honoured, a `User-Agent: planeter-client/<version>`; (e) **no `--insecure`, no `http://` ever** (a plain URL is refused with a sentence; tests use a local TLS terminator in dev-dependencies, as the assessment did); `--cacert FILE` **replaces** the trust anchors (the help says so in one sentence); (f) the server's `{code, message, hint}` error body is parsed and shown, and the TLS failures map to **one plain sentence each with the next step** (unknown issuer → "this server's certificate is not signed by a certificate authority this program trusts; if you know the server uses its own, pass `--cacert`"; wrong name; expired; unreachable; plain-http) from the assessment's texts table; the raw rustls reason appears only under `--verbose`. Exit codes: 0 ok, 1 the server refused, 2 usage, 3 network/TLS, 4 local prikk failure, 5 local state (files, keys).

## T2 — `planeter-client propose`

`planeter-client propose <https://host/owner/name> [--ref heads/x] [--proposal ID] [--title T] [--description-file F] [--dry-run]` in a local prikk repository: (1) ask the forge for its advertisement (the `have` offer of part 8) and the ref's **have-list**; (2) run the user's `prikk sync build <ref> --have <file> --output <artifact>` (the user's own keys; the helper never reads a seed); (3) **declare**: the patch ids of the artifact (ids only, from `prikk log --format json` of the blocks since the base) and the **base** block id it was built on (the tip of the advertised ref); (4) upload in the propose framing (`PLANETER-PROPOSE-1\n` + 8-byte big-endian metadata length + JSON + artifact, `Content-Length` exact) with the metadata of `docs/propose.md`; refuse locally, before uploading, anything the server would refuse by size (the advertised bound) with the sentence and the remedy; (5) print the result **in plain words with the next step**: "Proposed as proposal #… (revision 1). Your work is held for review on this server; no branch has changed. Reviewers can see it at <url>."; for `already_recorded`, `incomplete` (say: the server did not finish, send the same artifact again once the repository has recovered — and offer `--retry`), a quota refusal (the limit and the remedy), `needs_recovery`, `declaration_*`, `base_unknown`, `too_large`: **one sentence for the reason and one for what to do**, prikk's/the server's verbatim text only under `--verbose`. `--dry-run` builds and declares and prints what would be sent, uploading nothing. Never retries a non-idempotent step silently; the idempotent re-send is explicit.

## T3 — `planeter-client clone` and `fetch`

`clone <https://host/owner/name> [dir] [--trust-key <whole public key>…] [--no-adopt]`: download the archive (resumable) → local `prikk archive verify` → `init` → **show the carried maintainer keys with their whole public key in groups, and ask the user to type each one they trust** (interactive default; empty input skips that key; never a default "yes"; on a non-terminal, trust is given only through `--trust-key`, else the clone refuses and says how) → `trust maintainer add` for exactly the typed keys → `archive import --adopt` → `verify`; `--no-adopt` imports everything under `remotes/` and prints one sentence: **nothing is verified or trusted**. `fetch [dir]`: `GET` with `If-None-Match` → `archive` or per-ref bundle → local verify → `archive import` (lands under `remotes/`) → print what prikk reports (the classification of 0.56 when present) and the next step in plain words ("review it, then merge it yourself"); **freshness (RFC 004 D-8):** keep, per forge and repository, the highest `update_seq` and RefState id seen (state file under the user's state directory, not in the repository or the worktree) and refuse a served tip that is lower or not a descendant, with the sentence explaining a split view; if the advertisement does not yet carry `update_seq`/RefState ids, report that gap instead of faking it.

## T4 — Words, accessibility, identity, documentation

Messages in a catalog (English + Japanese draft, the `LANG`/`LC_ALL`/`--lang` choice; English by default; the same plain-words rules and retired-words test as the server's: the CLI says *proposal*, *revision*, *held*, *trust a key*, never *seal*, *adopt*, *intent*); output is plain lines, no colour needed to understand anything (honour `NO_COLOR`, colour off when not a terminal), no spinner or in-place redraw when not a terminal, progress as occasional whole lines; `--help` for each command with one example; `--version` prints the name, version, build commit and the prikk floor without network (the RFC 010 D-6 pattern). `docs/client.md` (what each command does, what it never does, the trust model in four sentences, the exit codes, exit-by-exit troubleshooting of TLS), CHANGELOG, STATUS, the glossary rows if a new word appears. Distribution (release assets, `cargo install planeter-client`) is **not** in this handoff.

## Non-change scope

No change to the server's routes beyond part 8; no signing code (ENF-2 must pass on the client binary too: extend the symbol check to it); no SSH; no `merge`/`seal`/`publish` command; no auto-update; no telemetry; no unsafe; no new dependency beyond T0's list without a rule-1 report.

## Acceptance criteria

T0's reports and the 3-OS job green; T1's tests (resume byte-identical, 304, redirect refused, token never printed, the TLS failure sentences for the five cases, proxy variables); end to end against a **real planeter server** (behind a TLS terminator) and real prikk: clone (typed keys, wrong key refused, `--no-adopt`), propose (the result sentence, `already_recorded`, a declared-patch refusal, a quota refusal), fetch (`304`, then a new state); a hostile server (redirect, a body longer than its length, a body shorter, a slow-drip, a huge error body) handled with bounded memory; the CLI texts pass the retired-words and plain-words tests in both languages; all earlier checks pass; every gate green (fmt, floor, pin, clippy, both test runs named, deny/audit, ENF-2 on both binaries, doc), CI green on all three systems.

## Prohibited shortcuts

No `--insecure`; no plain http; no token on a command line or in a log; no following a redirect; no silent retry of a non-idempotent step; no prefilled or defaulted key trust; no hard-coded user-visible text outside the catalog; no reading of a seed; no weakening of a test.

## Known risks

The helper is the first code that runs on strangers' machines against possibly hostile servers: every network read is bounded; every error is a sentence; trust is typed. Windows paths and permissions differ (the token-file check is Unix-only: say what Windows does instead and why). Large archives: streaming only.

## Required evidence and review-request format

Per phase: commits (hash → what); T0's rule-1 report and per-OS build requirements, sizes and times; the transcripts of each end-to-end flow (token and keys elided); the hostile-server tests; the texts table (English + Japanese draft) with the retired-words result; every gate with command and exit code and the advisory-database HEAD; deviations and open questions.
