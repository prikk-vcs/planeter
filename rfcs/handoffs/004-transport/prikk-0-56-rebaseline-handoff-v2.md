## Decisions (the architect's)
**D1 — How a failed accept is classified (A1).** Not "any exit 1 is incomplete": that would let anyone flag a repository read-only with one bad signature, and the measured refusals leave the tree untouched. Not "accept the orphans": the account the server gives would be false. **Decision: a failed accept is `Refused` only on positive evidence that the store did not change.** Take a **store signature** under the same lease, before the accept (together with `pending_before`) and after the failure: the sorted list of `(path relative to .prikk, size, mtime in ns)` of every regular file under `.prikk`, **excluding `*.lock`** files (prikk creates and removes those even on a clean refusal). Exit 1 without "lock conflict" is `Refused` **only if both** the signature **and** the pending set are equal to the "before" values; anything else (signature changed, or either could not be read) is `Incomplete(Failed)` as today (flag set, intent kept, artifact kept, recovery applies). Reuse the bounded walk of `store_size_limited` (same entry bound; if the bound is hit or a path cannot be read, the answer is "could not be read" = incomplete). Cost: report the time of the signature on a store with 5,000 and with 20,000 patches; if one signature takes more than 50 ms at 5,000 patches, stop and report before going on.
**D2 — The orphans are harmless and said so.** The measurement shows `doctor` errors 0 / warnings only (`PRIKK-DOCTOR-UNREACHED-OBJECT`), `verify` ok, and a resend completes. Recovery already counts that code as clean (A2). No change to recovery's logic beyond what D1 and B3 need. Add the sentence "a killed or failed accept leaves unreached patch and blob objects, no pending prefix" to the recovery module docs and to `docs/` where the recovery procedure is described.
**D3 — The "not listed" badge told something untrue (A3).** After a patch arrives only as received sealed history, the page says "neither held by this server nor in the history it holds" and one line below "found in history received here". Decision: the legend must be true in **every** case that shows no badge (received-only, discarded, repository restored). New texts (exactly these; the badge in English stays):
