## Change scope

**T1 — `tools/run-capped.sh` derives its limits from the machine.** Defaults (each overridable by the flags it has and by `RUN_CAPPED_CPU`, `RUN_CAPPED_MEM`, `RUN_CAPPED_JOBS`, `RUN_CAPPED_NICE`): **CPU quota = an eighth of the cores' worth, at least 200%, at most 800%** (32 cores → 400%, 16 → 200%, 8 → 200%), **memory = the smaller of 16 GiB and 40% of `MemTotal`**, **jobs = cores ÷ 4 between 2 and 8**, `nice 10`, `MemorySwapMax=0`. The measurement says a 400% quota lengthens the compile steps by under a minute on this host against a gate run whose wall is dominated by waiting tests, and halves their peak heat. The script **prints the numbers it chose and why**, and a clear message when `systemd-run` is absent (it then sets priority and jobs and says it is not capped). Tests: the derivation for 4, 8, 16, 32 and 64 cores and for 8, 16 and 64 GiB (a pure function, tested with fabricated inputs, not this host), the overrides, and the no-`systemd-run` path (a stand-in `PATH`). **This is the one place a default changes; say so in the report.**

**T2 — `tools/gates.sh`: the one gate script, `--tier commit|review|release`.** It replaces the copies of `gates.sh`/`run-gates.sh` that each reviewer keeps (the architect will use it; say what you removed from the repository, if anything). Common to all tiers: it runs **inside `tools/run-capped.sh`**; it uses **the compiler the release uses**, read from the **same source `planeter-pin-check` reads** (the pin in `ci.yml`, 1.99.1 today), via `RUSTUP_TOOLCHAIN` (refuse with a sentence, naming the `rustup toolchain install` command, if it is not installed; **never silently fall back to `stable`**); it prints the compiler version at the top of its output and the tier's step list; it works in **its own worktree of the commit named** (`--commit REV`, default `HEAD`) under `.git-exclude/tmp/arch/`; **it ends with a cleanup that runs on every exit path** (normal, a failing step, `INT`, `TERM`): `git worktree remove --force`, `git worktree prune`, and `rm -rf` of its scratch and (for the release tier) its target, **each by one explicit path it created**, never a glob and never a path it did not make; it records, for each step, wall time and the step's exit status in one table at the end (CPU-seconds and peak memory too when `systemd-run` and cgroup v2 allow: say how you read them, as the measurement did). Exit status = the first failing step's, after the cleanup.
- **`--tier commit`** (a developer before pushing; in the developer's own worktree, **incremental builds on**): fmt, floor-check, pin-check, clippy, and `cargo test` for the crates the diff touches (`git diff --name-only` to crates, `-p` for each; the whole workspace when `Cargo.toml`/`Cargo.lock`/`tools/`/`.github/` changed). It does **not** make a worktree or clean up one: it runs where it is.
- **`--tier review`** (the architect or a dev team member on someone else's commit): first **reads CI** for the exact commit (`gh run list --commit REV --json …`; prints each job's conclusion; **refuses to continue if CI is not complete and green** unless `--no-ci`, which says so loudly), then runs only what CI cannot: **the workspace tests with prikk once** (`--runs N` for more), `cargo deny check` and `cargo audit` against a **freshly fetched** advisory database (the tools pinned as the workflows pin them, installed once per machine into a scratch root the script manages and says where), the **sheet check**, and **what the change touches**: `doc` (`-D warnings`) when documents, public items or `Cargo.toml` changed; the **1.89.0 `check`** and the **publish dry run** only when a `Cargo.toml`, `Cargo.lock` or `rust-version` changed; **ENF-2 and `pin-check` when `.github/`, `Dockerfile`, `tools/` or the manifests changed**. It uses **one shared `CARGO_TARGET_DIR`, keyed by the compiler version and a hash of `Cargo.lock`** (`.git-exclude/tmp/gate-target-<rustc>-<lockhash>/`, deleted and recreated when the key changes; the script **removes older keys**), `CARGO_INCREMENTAL=0` (what CI sets: the measurement showed it saves 3 GiB and 9% CPU in a one-shot run), and says in its header that **a review's green is not a release's evidence**.
- **`--tier release`** (a release candidate and the tag commit): **a clean worktree and an empty target directory, always** (never the shared one; the script refuses a shared target here), the pinned compiler **and** the 1.89.0 `check`, **fmt, floor, pin, clippy, the test build, the workspace tests with prikk three times in a row and once without it**, deny, audit (fresh database), ENF-2, doc, the publish dry run (its own target), the sheet check, **and CI read as in the review tier**; it removes everything it made at the end, the 20 GiB included.
- **Safety of the cleanup:** a test that makes a worktree and then fails a step (`exit 7`), is interrupted, and in each case leaves `git worktree list` with its starting entries and no scratch (the measurement's demonstration, kept as an automated test in `tools/tests/`, runnable without a build: fake step commands).

**T3 — `docs/RELEASING.md`.** The paragraph "Run the gates capped (the development-machine budget)" becomes the description of the tiers and of `tools/gates.sh` (what each tier runs, what it reads from CI, why the release tier is clean, the compiler rule: **local gates run on the release's compiler, 1.99.1, never on `stable` by accident**), with the **derived limits** and their overrides, and with the one sentence that the budget is for the development machine and not the running service (keep). The release procedure itself is **not relaxed** (state that in the paragraph). Do not touch any other part of the document.

**T4 — The loaded repeats (documentation only).** `docs/RELEASING.md` and the header of `tools/repeat-under-load.sh` say (Amendment 1, principle 3): run loaded repeats **when a new or changed test uses timing, ports, processes or a terminal, or after an unexplained failure**, in the **confined** form (`--confine`) and in small numbers; not as a routine on every file. **No default of the script changes in this handoff** (the measurement of the confined mode is its own question: say what you would measure and do not change it).

## Non-change scope
No product code, no test assertion, no workflow, no change to what a release requires, no new dependency of the project (the script is POSIX `sh` and uses `git`, `gh` when present, `cargo`, `rustup`, `systemd-run` when present), no change to `docs/SCHEDULE.md`, `docs/STATUS.md`, the ledger or the threat model. No tag, release or upload.

## Acceptance criteria
`tools/gates.sh --tier commit|review|release` exists with the contents above; the derived limits are tested for fabricated machines; the cleanup test passes for a failing step and for an interrupt; the release tier uses a fresh target and refuses a shared one; the review tier refuses when CI is not green; the compiler is the pin or the script refuses; `docs/RELEASING.md` says it; all gates green **run through the new script's review tier on its own commit** (and its release tier once, as the proof); CI green on all eight jobs.

## Required evidence
Commits (hash → what, each compiling and passing the tests it touches); the script's help and the plan each tier prints; the derivation table; the cleanup test's output; **one real run of each tier** (the report quotes the step table: wall, CPU, exit), the review run showing the CI read; what you removed or replaced; deviations and open questions (say plainly what you could not show).
