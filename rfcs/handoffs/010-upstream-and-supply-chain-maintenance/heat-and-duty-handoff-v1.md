## Change scope (in this order; each is its own commit)

1. **A machine-wide lock for heavy jobs** in `tools/run-capped.sh` (`flock` on one file in a per-user runtime directory, found, not hard-coded: `$XDG_RUNTIME_DIR` or the temp directory): a second heavy job **waits**, saying who holds it (the command and its age) and giving up after a stated time with exit status 3 and a sentence; `--no-lock` exists for the script's own tests and says so loudly. The lock is released on every way out (a kill included: `flock` is held by the process, not by a file's existence). *Tests (`tools/tests/`): two jobs never overlap; the second says who holds it; a killed holder releases it; the give-up sentence and exit status; the cap's own tests unchanged. Mutation: the lock removed → the overlap test fails.*
2. **The sampler** (RFC 010 Amendment 2, item 8): during a run inside `tools/run-capped.sh`, every ten seconds one line to a file in the run's scratch: time, 1-minute load average, **the CPU temperature** (read from `/sys/class/hwmon/*` by sensor **name**, preferring `k10temp`'s `Tctl` and `coretemp`'s package, falling back to `/sys/class/thermal`; **none found → it says "no temperature sensor" once and goes on**, the run does not fail), the NVMe temperature if present, and the **three processes using the most CPU that are not in the run's cgroup** (command name only, no arguments, no paths). At the end the runner prints one block: peak and mean load, peak and mean temperature, the number of seconds above **the device's own reported limit minus 15 °C where the device reports one (the NVMe's `max`; `k10temp` reports none here: then no threshold is applied and the report says so)**, and the names that were hot outside the cap. **Nothing in this block changes a default.** *Tests: a fake sysfs tree (found by name; absent; unreadable); a fake `ps`; the block's text; the run's exit status is the command's.*
3. **Measure, once, on a quiet machine** (`uptime` below 2; nothing else heavy; the owner's desktop use is what it is, say what was running): (a) an idle baseline of ten minutes; (b) the commit tier's test step and the review tier at the **default cap, at half of it and at a quarter**, alternated, one run each, with a **ten-minute rest** between runs (the rest is recorded too); (c) the temperature curve from the start of each run to ten minutes after it ends (how long the machine takes to cool); (d) **what was hot outside the cap** at any time (this answers whether the gate is the heat). Report the tables and the raw sample files. **No default changes in this commit.**
4. **The review tier derived from what CI cannot do** (RFC 010 Amendment 2, principle 5): `tools/gates.sh --tier review` runs, instead of the whole set, **only the test binaries that contain a test that skips in CI for want of bubblewrap or prikk** (derive the set from the skip marker the tests print, with one CI-equivalent listing run that executes nothing: `cargo test -- --list` plus a grep of the sources for the skip helper; **do not keep a list by hand**), plus the steps it has now. **A coverage proof first, in the report:** the set of tests CI skips (from CI's own log of the last green run) is **a subset of what the derived review tier runs**, test by test, and the number of tests the old review tier ran that the new one does not, with the reason each is covered by CI. **Mutation:** a test that needs bubblewrap and is broken on purpose → the new review tier fails; a test that CI runs and is broken → CI fails and the review tier does not need to. The release tier is unchanged. `docs/RELEASING.md` says it.
5. **The docs-only tier** (principle 7), a fourth tier named in the script (`--tier docs`): refuses unless **`git diff --name-only <evidence commit>..<commit>` names only files under `docs/`, `rfcs/`, and the root `CHANGELOG.md`, `README.md`, `ROADMAP.md`** (the base is a required argument: the last commit whose release tier is green and verified); it runs fmt, floor-check, pin-check, deny, audit, doc, sheet-check, `package-keys` and **the test binaries that read those files** (derived: test sources that open a path under `docs/`, `CHANGELOG`, `README`, `ROADMAP`), and prints that it is **not** a release tier. **A tag commit may use it only when the diff from the evidence commit is docs-only**; one Rust file in the diff and it refuses and says to run the release tier. *Tests: the refusals; the derived set; a docs change that a doc-reading test pins (mutation: change a pinned sentence → the tier fails).*
6. **`docs/RELEASING.md`'s paragraph** ("the development-machine budget"): the three parts (peak, duty, concurrency), the lock, that **everything heavy goes through the runner** (a single crate's tests, a mutation run, a stress run, `cargo package`), the sampler and where its file is, the derived review tier and the docs-only tier and their limits, and the rule that the architect verifies a log instead of re-running it (what is checked: header commit, snapshot hash, exit codes, counts). **Dev machine, not the running service.**

## Non-change scope
No default of `tools/run-capped.sh` (quota, memory, jobs, nice) changes; **no duty rule or temperature limit is added in this handoff** (the data comes first; the architect derives the rule from it in a following handoff); the release tier and the evidence it requires are unchanged; no product code, no dependency, no `unsafe`; no edit of `STATUS.md`, `SCHEDULE.md`, the ledgers, the threat model or a security review.

## Acceptance criteria
Items 1 to 6, each with its tests and mutation; the measurement tables (item 3) in the report; the coverage proof (item 4) with the counts; CI green; the report states **how long each of your own runs took and when each started and ended** (so that the architect can see the duty of this very handoff).

## Required evidence
Commits (hash → what, one per item); each tool's tests and mutation; the sample files and the tables of item 3; the coverage proof; the new tiers' output on the head; the RELEASING diff; deviations and open questions. Final reply: the review-request path only.
