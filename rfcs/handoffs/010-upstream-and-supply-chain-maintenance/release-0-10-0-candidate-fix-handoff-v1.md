## Why (1) is decided, not left open
crates.io never takes a version back. A private key in a published tarball is, however throw-away, a thing every secret scanner flags in the crate for ever, and a reader cannot tell at a glance that it protects nothing. `planeter-client` already excludes its fixtures for exactly that reason, and its tests are then run from the repository, where the fixtures are. The same rule for `planeter-auth`: **tests that need fixtures are the repository's, not the package's.** (A package's job is to build and be read; the workspace is where it is tested.)

## Change scope

Then: `cargo package --list -p planeter-auth --locked` shows no file under `tests/fixtures/` and **no `.pem`, `.key` or `*key*.json`**; the package **verifies** (`cargo publish --dry-run -p planeter-auth` builds it); the tests that read the fixtures still pass **in the workspace**.
