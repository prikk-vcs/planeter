## Change scope
1. **The sheet step generates its own sheet.** In the **review tier** the step is: generate a sheet from the worktree's live catalogs into the run's scratch (`planeter-i18n-sheet --lang ja --out <scratch>/sheet.md`) and `--check` it. It then **needs no file and no `--sheet`**; `--sheet FILE` stays as an option that **adds** a check of that file too (the architect's reading sheet), and a failure of *that* check is reported as "the supplied sheet does not match the catalogs" (naming the file) and not as a step of the commit. The **release tier** keeps checking **the sheet the owner reads**: `--sheet` is **required** there (a release is not tagged on a sheet nobody named), and the script says so before it starts anything. Update the plans, the help, `tools/tests/gates.sh` (a review plan without `--sheet` has the generate-and-check step; a stale supplied sheet fails only its own check; the release tier refuses without `--sheet`, exit 2, nothing ran, cleaned up) and `docs/RELEASING.md`'s tiers paragraph.
2. **The shared target says who may use it, and the script refuses what is unsafe.** The marker file the script writes in each shared target directory gets a short text: "Made by tools/gates.sh for its own fresh worktrees. Do not point another checkout at it: a cached workspace artifact can be taken as current for older files and be a different commit's. To use it by hand, make a fresh worktree." **And the script checks, in the review tier, that its worktree is fresh** (it made it a moment ago: the files' times are newer than the directory's marker, or the worktree did not exist before this run) and says so in its header line; if it is ever run against an existing checkout, it **refuses the shared target** (uses a target of its own, or stops with a sentence), never reuses it. `docs/RELEASING.md` says the same in two sentences (including: the shared target is a cache that saves third-party dependencies and the disk, **not** the workspace's own compile). A test: a fake existing checkout is refused the shared target.
3. **Report, do not change:** whether the **release tier's** empty target and the **commit tier's** own checkout are free of the same hazard (they should be: say why in one sentence each).

## Non-change scope
No product code, no change to what a release requires, no other tool, no new dependency, no change to the ledger, SCHEDULE, STATUS or the threat model, no tag, release or upload.

## Acceptance criteria
The review tier runs to its end with no `--sheet` and no stale file; a supplied stale sheet fails only its own check, named; the release tier requires `--sheet`; the marker explains the cache and the script refuses the shared target for a non-fresh checkout, tested; RELEASING updated; the new tool tests pass under `cargo test` (`shell_tools.rs`); a real review-tier run of the script on its own commit (no `--sheet`) and CI green on all eight jobs.

## Required evidence
Commits (hash → what, each compiling and passing the tests it touches); the new plans; the tests' names; one real review-tier run's table without `--sheet`; deviations and open questions.
