# RFC 014 — The provider side of step 1: the one private-address allowance, a JWKS refresh that cannot be answered stale, and the session lifetime — Implementation Handoff (v1)

| Document | Fourth handoff of RFC 014 step 1 (D-11, amendment 1, D-13). ## Change scope

**T1 — The allowance (D-11).** `PLANETER_OIDC_ALLOW_PRIVATE_ISSUER=on` (default off; any other value is refused at start with a sentence). When on, the egress guard used **for the OIDC provider only** (a separate guard instance; no other outbound path is changed: webhooks and every other caller keep the strict one) admits **private, loopback, link-local and CGNAT addresses for exactly one host: the configured issuer's host (name or literal address, port ignored for the comparison, case-insensitive, no wildcard, no suffix match)**, still **https only**. Everything else about the guard stays: it resolves, classifies **every** resolved address, and connects only to the **pinned** addresses (so DNS cannot rebind between check and connect). Then: **every endpoint the provider's discovery names (authorization, token, JWKS, userinfo if present) must have that same host**; one that does not is refused as today (an `OidcError` that says which endpoint and nothing more); the discovery document's own `issuer` must equal the configured issuer exactly (as now). **Redirects:** whatever the confined `curl` does with a redirect today, show it, and show that a redirect (from the issuer's host or to any host) that leads to a private address **other than the issuer's** is refused; if `curl` follows redirects, restrict it (`--max-redirs 0` for the OIDC calls) and say so. The start-up line says the allowance is on and for which host (counts and host only, no secret); a start with the allowance on and **no** provider configured prints a sentence and does not start (it would mean nothing). **Tests (the real built server where it can be shown; a stand-in provider on `127.0.0.1` with a self-made certificate trusted by a test-only mechanism: say which, the product has none, Open question 4 of the RFC):** allowance off → a provider on loopback is refused (as today: the test exists, keep it); on → the full code flow with PKCE, nonce and an EdDSA ID token completes against the stand-in and the person is signed in (a linked account) and a **second private host named in discovery is refused**, a **redirect to another private address is refused**, an `http` issuer is refused, a **hostname that resolves to a private address and a public one** is refused when it is not the issuer's host, and the pinned address is the one used (a test whose resolver changes its answer between the check and the connection). **Mutations:** the allowance applied to every host; endpoint hosts not compared; the guard shared with other callers; `http` accepted.

**T2 — The JWKS refresh is `no-cache` (ID-7).** The **refresh** of the JWKS (the one made after an unknown `kid`) is sent with the request header `Cache-Control: no-cache` (and `Pragma: no-cache`); the first, cached fetch is not. This needs one optional header list on `FetchRequest` (the confined `curl` gets `-H` arguments from a closed, validated set: never a value from a request or a provider); say what you changed in `fetch.rs` and show the arguments the confined `curl` is given (a transcript from a test that records them). Tests: the unknown-`kid` path sends the header and the ordinary path does not; a stand-in provider that rotates its key (publishes the new `kid` only after it became the signer) and a **caching stand-in in front of it that answers a request without `no-cache` with the stale JWKS for 300 s**: the sign-in right after the rotation **succeeds with the fix and fails without it** (show both). Mutation: the header dropped.

**T3 — `PLANETER_SESSION_HOURS` (D-13).** Default **168** (today's 7 days; the default does not change behaviour); accepted 1 to 720; anything else is refused at start with a sentence (not clamped silently). It sets the session's server-side expiry and the cookie's lifetime together (both `sessions.create(…)` sites and both `set_cookie` calls use one value from one place: no second constant). The start-up line names it. **A session already created keeps the lifetime it was created with** (state this in the result and in a test). Tests: the value reaches the expiry and the cookie (real router); a session expires at exactly its lifetime and not a second before (a manipulated clock); invalid values refuse the start; the default equals the old constant (a test that fails if someone changes one without the other).

**T4 — Held, not built (tests only).** (a) **planeter reads no `name` and no `preferred_username`**: a stand-in provider whose userinfo endpoint would answer with a hostile name must receive **no request** (count the requests: discovery, JWKS, token only); and the ID-token claims struct has no field for either. (b) **No email is stored from a provider**: sign in through a stand-in whose ID token carries `email` and `email_verified: true`, and show that the account row's email is unchanged (this release stores none; RFC 014 D-2's "only when verified" is for a later step). These two tests exist to stop a later change from adding either quietly.

**T5 — The words.** Messages (start-up lines and refusals) in the server's catalog where a person reads them, **English and Japanese**, one sentence each with what to do; they ship **flagged**; give `--status`. Do **not** write `docs/accounts.md` (the next handoff), but list in your report each fact the document must state: the allowance and its risk (the operator set the issuer; the provider's host may be a private service), that a person disabled at the provider keeps a planeter session until it ends so **the operator disables them in both places**, the recommended lifetime with a provider (24 hours or fewer), and that planeter sends no `prompt` or `max_age` (ID-4).

## Non-change scope
No page, no route, no API, no OpenAPI change, no provisioning, no refresh-token use or storage (RFC 014 open question 7 is the owner's, and the recommendation is not now), no `prompt`/`max_age` sent, no change to the foundation's services or schema, no private certificate authority (RFC 014 open question 4: later, its own handoff), no new dependency, no `unsafe`. No sign-off record, baseline, `ja.signed` or `SignOff`. No tag, release or upload.

## Acceptance criteria
With the allowance on, a provider on a private address works and only that host; with it off nothing changed; the JWKS refresh carries `no-cache` and the rotation test passes with it and fails without; the session lifetime is one setting used everywhere with the old default; planeter makes no userinfo request and stores no provider email; all gates green with tests with prikk three times in a row; CI green on all eight jobs; `tools/repeat-under-load.sh 20` on each new test file clean.
