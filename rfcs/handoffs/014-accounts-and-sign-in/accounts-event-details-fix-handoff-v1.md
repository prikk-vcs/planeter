# RFC 014 — The account log must not carry English sentences inside other languages — Fix Handoff (v1)

| | |
|---|---|
| Document | Found by the architect reading `accounts-tokens-operator-review-request.md` (open question 1, "1 repositories") and following it to its cause. The foundation's service writes **generated English prose into the stored `detail` of an event**: `"{n} session(s) ended"` (and *session(s)* is a retired word in a user message, IS-49), `"{owner}/{name} {role}"`, and for a token `"name; write, 2 repositories; until 2026-12-01"`. The holder's log sentence is `トークン ({detail}) を、{by}が作成しました。` in Japanese: **an English fragment, a plural error ("1 repositories") and a retired word inside a Japanese sentence**, in the one place the person reads about their own account (the operator's `show` today, step 2's security page next). **Stored history must be data, not prose**: a sentence in English written into a row today stays English forever and can be neither translated nor corrected. 0.10.0 is not released, so no stored row has the old shape outside tests: this is the cheapest moment, and a later migration would be real work. |
| Status | Assigned 2026-11-25 (SCHEDULE D-130), **before** the token commands are released; the rest of `6583553` is approved. |
| Basis | `crates/planeter-auth/src/accounts.rs` (every `AccountEvent::new` with a generated detail: the sessions-ended count, the role events, `create_token_for`), `crates/planeter-auth/src/events.rs`/`text.rs` (the event type, `detail` cut/escape), `crates/planeter-web/src/catalog/{en,ja}.rs` (`account.event.*`, `account.by.*`, and the plural facility `plural_msg`), `crates/planeter/src/operator_account.rs` and `operator_token.rs` (where the sentence is rendered from "the event just written"), the language rules (`language_rules.rs`: retired words), RFC 014 D-7. |
| Audience | Dev team. Return a short review-request package. |

## Change scope
1. **Which details are data and which are the operator's words.** Free text typed by a person stays text, shown as it was typed after the display-safe rules: a **reason** (`disabled`), a **token name**, a **display name**. **Everything the system generates becomes language-neutral data**: the count of ended sign-ins (`session_ended`: the digits only), a role event (`owner/name` and the role as its stable code `read|write|maintain|admin`, tab-separated), a token event (the name, the scope code `read-only|write|full`, the number of limiting repositories, the end date `YYYY-MM-DD`, separated by a character that cannot occur in a display-safe name: the tab), an identity link (the issuer's host, as now). **Document the exact field order of each kind in one place (the event type's doc comment) and give each kind a typed constructor and a typed parser** (`EventDetail::TokenCreated { name, scope, repositories, until }`, etc.), so that nobody builds or reads these strings by hand again. A detail that cannot be parsed (an older or corrupt row) is **shown as nothing, never as raw text, and never breaks the page or the command** (test).
2. **Render in the viewer's language, from the typed form.** One function, `render_event(event, lang) -> String`, in the catalog layer, used by **both** the operator commands' "the sentence the holder will read" and (step 2) the page, so they cannot differ. New or changed catalog messages: each kind's sentence gets the parts it needs as placeholders with their own words, e.g. English "Access token "{name}" ({scope}, {repositories}, until {date}) was created by {by}." with `{scope}` rendered by the catalog's scope words (the same words the operator's token commands and the pages already use: *read-only*, *write*, *full*), `{repositories}` by a **plural message** ("all repositories you can reach" / "1 repository" / "{count} repositories") and the Japanese with its natural order and counter (…件/…個 as the project's glossary uses for repositories: check `docs/glossary/ja.md`), `{date}` through the project's date function in the viewer's language. **No English or Japanese word is ever stored; none of the retired words (*session(s)*, 保持, 預かる) appears in a message.** Roles are rendered with the catalog's existing role sentences' short names; the sign-in count with a plural message ("1 sign-in ended" / "{count} sign-ins ended").
3. **Tests:** every event kind rendered in English and Japanese from its typed form (a table), the plural boundary (0, 1, 2) for repositories and sign-ins, a hostile token name (escapes visible, nothing breaking the sentence), an unparsable detail rendered as nothing, **no stored detail contains an ASCII letter run that is a word of the project's catalogs** except the three role codes and the three scope codes (a test over every event the service can write, with a canary name that is not a catalog word), the command's printed sentence **equal** to `render_event` of the event just written (existing property: keep the test), and the existing tests updated to the new typed form. Mutation: a constructor that writes a prose detail (caught by the "no word" test).
4. **The catalog and the owner's reading:** these messages replace the foundation's thirteen `account.event.*` sentences' use of `{detail}` for generated parts. `planeter-i18n-sheet --status`: give the new count (the messages already counted stay counted; changed ones are "changed or new" — the baselines are not edited) and **regenerate the reading file** `accounts-tokens-reading-order.md` so the owner reads the final wording once, with the event sentences grouped (the holder's log) after the operator's messages.

## Non-change scope
No schema change (the `detail` column and its 200-character cut stay: the typed forms are short and a check proves the longest legal event fits), no new column, no page, no route, no change to what the commands do or to their exit codes, no change to the foundation's other services, no new dependency, no `unsafe`, no sign-off record, baseline, `ja.signed` or `SignOff`, no tag, release or upload.

## Acceptance criteria
No stored detail holds generated prose; every event kind renders correctly in both languages, with correct plurals and no retired word; the commands print exactly what the holder's log will render; an unparsable detail breaks nothing; all gates green, tests with prikk 0.58.0 three times in a row; CI green on all eight jobs.

## Required evidence
Commits (hash → what, each compiling and passing its tests); the table of every event kind with its stored form and its rendering in English and Japanese; the "no word" test and its mutation; the longest legal event's length; `--status` and the regenerated reading file; the gates in a clean worktree (fmt, floor, pin, clippy, tests with prikk three times in a row and without, `cargo deny`, `cargo audit` on a fresh database, ENF-2, doc, msrv); deviations and open questions.
