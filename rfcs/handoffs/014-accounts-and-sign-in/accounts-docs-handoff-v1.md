## Change scope

**T1 — `docs/accounts.md`.** Plain words, for two readers, in this order. **No promise beyond what is built; nothing about steps 2 and 3 except one honest paragraph "What is not here yet".**
- **For the person who runs the server (the operator):** what an account is (a handle, a display name, how it signs in: a local password and/or a linked identity at the provider; no email is used to find or link anyone); **the handle rule** (lowercase ASCII, 1–39, case-insensitive uniqueness, never changed, never reused; what happens to older mixed-case handles: reported by `account list --check`, never renamed); every command of `planeter operator account …` and `token …` with one worked example each and **every refusal's sentence** (copied from the catalog, held by a test as `keys.md`'s are), the exit codes (0/1/2/5; 3 and 4 not used, and why), **that they run beside a running server** (and `key add` does not); **passwords** (read from the terminal or a file descriptor, never an argument or an environment variable; `stty sane` if echo stays off; the password rule: 12–128 characters, Unicode-normalized, not the handle, not on the embedded common list; why no email reset exists); **tokens** (shown once on one line of standard output or written to a 0600 file made exclusively; scope in words; expiry 1–365 days, default 90; `--repos`; revoke and disable refuse a token at the next request; the operator-made token is recorded as such); **disable, never delete** (what it does at once, the repositories it can leave without an administrator, enable, why a handle is never reused); **roles in one plain sentence each**; **the account log** (what is recorded, in whose words, never a secret or an address); **sign-in providers**: `PLANETER_OIDC_*`, link by `(issuer, subject)` only, what the provider told us (ledger ID-1…ID-10, each in a sentence and none stronger than the ledger: **"tested with sui-id {version} on {date}" is not written anywhere yet; the interoperability test has not run**), `PLANETER_OIDC_ALLOW_PRIVATE_ISSUER` **with its risk** (the issuer's host **and port**, one authority and nothing else on that machine; https only; no private certificate authority yet; redirects not followed), **`PLANETER_SESSION_HOURS`** (default 168, 1–720, **recommended 24 or fewer with a provider**), **that a person disabled at the provider keeps a planeter sign-in until it ends, so the operator disables them in both places**, that planeter sends no `prompt` or `max_age` and reads no `name`/`preferred_username`, asks for no userinfo and stores no provider email, and that the JWKS refresh is sent `no-cache`.
- **For a person with an account:** how to get a token from the operator and use it (`planeter-client`'s `--token-file`); what each scope lets the token do (and that **a `write` token cannot deliver**); what the log says about them; who to ask. No promise of a page.
- **What is not here yet** (one paragraph): self-service pages (tokens, password, sessions, security log: step 2), provisioning and a collaborators page (step 3), a second factor (the provider's job), email recovery (never in planeter), a periodic check that a person still exists at the provider (the owner's open question 7), organizations' lifecycle (RFC 015, later), account deletion (never: disable).
- **The development machine is not mentioned** (this is a user document; the gates' budget lives in `RELEASING.md`).

**T2 — Held by a test, as `keys.md` is.** `crates/planeter-web/tests/accounts_doc.rs` (or beside `keys_doc.rs`): the document contains the catalog's sentences word for word for every refusal and result it quotes (read from the catalog, English), cites the ledger rows that exist (ID-1…ID-10, PK ids), names every environment variable the server reads for accounts and providers (the test reads the variables from the source, as the `USAGE` test does, and fails if one is missing from the document), lists every command and every flag its `--help` lists, and **never uses the words the language rules retire** (*session(s)* in a user-facing sentence; use "sign-in"), nor "retired/revoked" about keys. A link-check for the links it makes.

**T3 — Links.** `README.md`: one line in the documents list and the "Not yet" list updated honestly (accounts and tokens made by the operator now exist; self-service pages do not); `docs/client.md`'s "The token" points to it (one sentence; the paragraph written for 0.10.0 stays); `docs/keys.md` does not need to change; `docs/deliveries.md` only if it names who may deliver (a `full` token of a maintainer: link). `docs/accessibility.md`: **no change** (no page was added).

**T4 — The owner's reading plan: `accounts-0-10-0-reading-order.md`** in the format of `keys-0-9-0-reading-order.md`, **regenerated from the sheet** (`planeter-i18n-sheet`), covering **all 154** messages newer than the sign-off, **grouped in the order of use** so that the owner can stop after any group and what is read is complete in itself: (1) *the account commands* (create, set-password, disable/enable, link, grant/revoke, list/show and their errors); (2) *the token commands*; (3) *the person's own log* (the sentences of `render_event`, with the plurals as "one ‖ other" and the role and scope short names); (4) *the provider and start-up lines* (the six); (5) *what a provider-verified person sees when disabled* (the three of the foundation). Counts per group must equal the tool's total (154) and be checked by the test that checks the file (as the earlier reading files were). Say which group the owner should read first if only one is read (the log: it is what a person sees about themselves), and the words the dev team would like looked at (the role short names 読み取り/書き込み/メンテナー/リポジトリの管理者, the scope words 読み取り専用/書き込み/完全なアクセス, the plain-sentence fallbacks).

## Non-change scope
No product code, no catalog text (the quoted sentences are read, not changed: a wrong or unclear one is **reported**, with the file and key, not edited here), no new feature, no page, no change to `docs/RELEASING.md`, the ledger, SCHEDULE, STATUS or the threat model (the architect writes the threat-model update and the security review), no sign-off record, baseline, `ja.signed` or `SignOff`, no tag, release or upload. The document names no sui-id release and no "tested with" claim.

## Acceptance criteria
`docs/accounts.md` exists, every claim in it is held by the test, the catalog, the ledger or the code; the README and the client document link it; the reading plan covers all 154 messages in five groups with counts that equal the tool's; gates green (`tools/gates.sh --tier review` on the commit is enough for a documents-and-tests change; say so); CI green on all eight jobs.

## Required evidence
Commits (hash → what, each compiling and passing the tests it touches); the document's outline and the test's list of what it holds; the reading file's counts against `--status`; every wrong or unclear catalog sentence found while quoting (reported, not changed); the review-tier gates table the script printed; deviations and open questions.
