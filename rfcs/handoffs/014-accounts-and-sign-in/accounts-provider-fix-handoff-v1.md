## Change scope
1. **The allowance is for the issuer's authority.** `EgressPolicy::allow_private_for_host` becomes **host and port** (the port is the URL's explicit port, else 443 for https; the issuer URL gives both): a private address is admitted for a request **only when its host and its effective port both equal the issuer's**; another port of the same host is judged as any private target and refused. `with_endpoints_on_issuer_host` compares **host and effective port** (and scheme `https`) of the authorization, token and JWKS endpoints with the issuer's, and its refusal names the endpoint only. Update the guard's doc comment, `docs/RELEASING.md`/the facts list you gave for `docs/accounts.md` (fact 1: "one host" becomes "the issuer's host and port") and the RFC-facing wording in the messages if any says "host" alone (the start-up line names the host: it may name `host:port` when the port is not 443; show the line). Keep the English and Japanese messages' meaning and count; if a message changes, give `--status`. **Tests:** a discovery document naming the token endpoint on **the same host, another port** is refused with the endpoint named and **that port's stand-in receives nothing**; the same for the authorization and JWKS endpoints; the guard alone refuses `https://idp.test:9999/` when the allowance is `idp.test:8443` and admits `https://idp.test:8443/`; an issuer with no explicit port allows 443 and refuses 8443; a literal-address issuer likewise; the literal `[::1]` form. **Mutation:** the port ignored again → caught.
2. **~~The load script's default becomes the confined one~~ — withdrawn (2026-11-26, SCHEDULE D-138).** The first version of this handoff asked for it on the strength of 2 failures in 20 runs of one test on one machine; the owner's review of the approach asked for the long-term view first. Leave `tools/repeat-under-load.sh` as it is (it stays available, with `--confine`), change no default, and do the **measurement first**: `gate-cost-measurement-handoff-v1` decides what the defaults should be, from numbers.
3. **Say what the budget is for, so it is not mistaken for something else.** The owner's concern (2026-11-26) is the **development machine's** resource use (the gates, the test suite, the loaded repeats and builds that run on a developer's computer), **not the resource use of the running service in production**, which is a different matter governed by RFC 011's cost model and the server's own admission settings (`PLANETER_PRIKK_MEMORY_BUDGET_MB` and the rest). Add one sentence to the header of `tools/repeat-under-load.sh` and `tools/run-capped.sh` and to `docs/RELEASING.md`'s paragraph (and call it the **development-machine budget** there, not "the project's CPU budget") saying that it limits what *running the project's tests and gates* may take from a developer's computer, and says nothing about what the server uses when it serves.
4. **Answers to your open questions:** the endpoint-host rule applies only with the allowance on: **yes, as built** (with it off a provider on other public hosts works as before, and D-11 ties the rule to the allowance); the visibility of a forgotten allowance beyond the start-up line: **no extra output** (the start-up line and `docs/accounts.md` are enough; do not add command output).
