# RFC 014 — The server's `--help` must list the provider settings, and a failed test must not leave a server running — Fix Handoff (v1)

| | |
|---|---|
| Document | Two findings from `accounts-docs-fix-review-request.md` (`fb2e258`, otherwise approved). **(1)** `planeter --help` (`args::USAGE`) lists no provider setting: not `PLANETER_LOCAL_PASSWORDS`, nor `PLANETER_OIDC_ALLOW_PRIVATE_ISSUER` or `PLANETER_SESSION_HOURS`, because the `USAGE` test scans `main.rs` and `config.rs` and not `provider_env.rs`. The README promises that `planeter --help` lists every variable the server reads; the operator's first reference is silently incomplete. The dev team read the main help as "a flagged, signed-off message": **it is not** — `USAGE` is a plain English constant in `args.rs`, not a catalog message, so listing the settings in it touches no sign-off. **(2)** A built-server test that fails before its `stop()` **leaves its server running**: the dev team found three left behind after failing mutation runs, and the same helper shape is in nine test files. A leaked server holds a port, a database and memory on a developer's machine until someone notices: exactly the local resource consumption the owner asked us to take seriously (RFC 010 Amendment 1, "a gate run leaves nothing behind"). |

## Change scope
1. **`USAGE` lists the three settings** (one line each, in the style of the others, plain English, in the `environment:` block): `PLANETER_OIDC_ALLOW_PRIVATE_ISSUER` (`on` or `off`, default `off`; the issuer's host and port may be on a private address), `PLANETER_SESSION_HOURS` (1 to 720, default 168; how long a new sign-in lasts), `PLANETER_LOCAL_PASSWORDS` (`on` or `off`, default `on`; `off` needs a provider). **Extend the `USAGE` test to scan `provider_env.rs` as well** so that a variable read there and missing from the help fails it (and show it failing once by removing one line: the mutation). Check for any other environment variable the server reads in any source file that the test does not scan (`grep -rn 'env::var\("PLANETER_' crates/*/src`) and list each with its place in the help or a reason it is not listed (a test-only variable, e.g. the failpoint, stays unlisted: say so).
2. **A server a test starts is always stopped.** Give the built-server helper a **`Drop` that kills the child and waits for it** (the whole process group if the server starts helpers: the server runs prikk through bubblewrap; say what you kill and how, and that a graceful stop in the test still works as before: `stop()` becomes "stop now and record that it was stopped"), put it **once** in a shared helper under `crates/planeter/tests/common/` and use it from every file that has the shape (nine files: list them). **Show it:** a throwaway test (not committed) that starts a server and fails an assertion; `ps` before and after shows no server left (the same for a panic and for the test binary being killed by `timeout`: say what is and is not covered: a `SIGKILL` of the test binary itself cannot run `Drop`, and `--die-with-parent`/`PR_SET_PDEATHSIG` on the child can cover that if it can be done without `unsafe`; if not, say so). **No test assertion changes.**
3. **Decided from the review:** an existing sign-in made by a password **stays valid** after `PLANETER_LOCAL_PASSWORDS` goes `off` (as built); add **one sentence** to `docs/accounts.md`'s subsection on the setting saying how to end such sign-ins at once if the operator wants to (`account disable` then `account enable`, or `account set-password`, per account) and that otherwise they end within `PLANETER_SESSION_HOURS`; the document test follows.

## Non-change scope
No behaviour of the server, no catalog message, no schema, no new setting, no dependency or `unsafe`, no sign-off record, baseline, `ja.signed` or `SignOff`, no tag, release or upload.

## Acceptance criteria
`planeter --help` lists every variable the server reads (the test proves it for all source files, or each exception is reasoned); no built-server test leaves a process behind after a failure (shown); the document sentence is added and held; `tools/gates.sh --tier review` green on the commit; CI green on all eight jobs.

## Required evidence
Commits (hash → what, each compiling and passing the tests it touches); the new help lines; the `USAGE` test's mutation; the list of nine files and what the helper kills; the `ps` evidence; the review-tier table the script printed; deviations and open questions.
