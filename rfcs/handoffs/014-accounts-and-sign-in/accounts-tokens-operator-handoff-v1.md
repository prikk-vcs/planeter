# RFC 014 — `planeter operator token …`: the operator mints, lists and revokes a person's tokens — Implementation Handoff (v1)

## The commands

```
planeter operator token create HANDLE --name TEXT --scope read-only|write|full [--expires-days N] [--repos OWNER/NAME[,OWNER/NAME…]] [--out FILE]
planeter operator token list HANDLE
planeter operator token revoke HANDLE ID
```
All take `[--lang en|ja]` and are described by `planeter operator --help` and `planeter operator token --help`.

## Change scope

**T1 — `create`.** One `AccountService` method (new, beside `grant_role`: one `BEGIN IMMEDIATE` transaction, `create_token` and the `token_created` event inside it, a closed error, a refusal changes nothing; `by = operator`; the event's detail is the token's **name and scope and expiry date only**: never the token, its id's hash or any part of the secret). Rules, all from the foundation and not re-invented: the account exists and is **not disabled** (a sentence says to enable it first); the name is 1–60 display-safe characters (**refused, not escaped**: the operator typed it); `--expires-days` is 1–365 and **defaults to 90** (the help says so; there is no token without an end); `--scope` is required and is one of the three; `--repos` (optional) limits the token to the named repositories, each of which must exist, **at most 20**, deduplicated, and the scope's words say so in the result; at most 200 unexpired tokens per account (the foundation's rule: the refusal sentence says to revoke one first). **The secret** is `mint_token()`'s `plt_…` value; only its hash is stored (as today).
  - **Showing it once.** By default the token is printed to **standard output on one line, and nothing else goes to standard output** (so `TOKEN=$(planeter operator token create …)` works); everything else — what it is, its scope in plain words, its expiry date, "this is the only time it is shown", and for `full` the sentence "This token can do everything the account can, including delivering a branch" — goes to **standard error**. With **`--out FILE`** the token is written to the file instead and **not printed at all**: the file is created **exclusively** (refused if it exists, no overwrite, no following of a symlink), **mode 0600 from the moment it exists** (create with the mode, not chmod afterwards), in an existing directory, and the line "The token was written to FILE (mode 0600). Give that path to `planeter-client --token-file`." is printed. A failed write leaves **no token stored** (write the file first, then store the hash, and if storing fails remove the file; or the reverse with a rollback: say which and show both failure orders in the tests). The token is in **no log, event, error, `ps`, environment or database** (canary test as for passwords).
  - The result also says the **id** (the public 16-character identifier) so the person and the operator can refer to it in `list`/`revoke`.
**T2 — `list`.** For one account, newest first, at most 200 (the foundation's bound), columns: id, name, scope in words (read-only / write / full), repositories (all of the account's access, or the named ones), created, last used (or "never"), expires, **and "expired" or "revoked" is not shown: expired ones are listed with their date, revoked ones are gone**. Never a hash or a secret. Tokens created before 0.10.0 show `(created before 0.10.0)` and no creation date. Read-only; it also waits for a held lock (the busy sentence, exit 5).
**T3 — `revoke`.** `token revoke HANDLE ID`: by id **and** holder (the foundation's rule; an id of another account's token is "no such token" and nothing is written), one transaction with the `token_revoked` event (name only). It takes effect **on the very next request**. A token already gone or never existing: refusal, exit 1, nothing changed (as `disable` of a disabled account).
**T4 — Frame.** Exactly the account commands' frame: no process lock; exit codes 0/1/2/5 (3 and 4 not used, `--help` says why); the database must exist; messages in the catalog (`operator.token.*`), English and Japanese, one sentence each with what to do, the project's plain words and the glossary (no 保持, no 預かる; *session(s)* is a retired word in a user message: use "sign-in"); they ship **flagged** and the reading file (`accounts-tokens-reading-order.md`) lists them in the order of use; `--status` line given. Never read `PLANETER_REPOS_ROOT` (except where `--repos` needs the repository list: then read it **through the database's repository table, as `grant` does**, and say if you could avoid the file path) or any secret of the server.
**T5 — Tests (the real built server beside the commands; real prikk where the repository is read).**
  - (a) `token create` then **the token works at once** for `planeter-client`-style bearer requests and **is limited exactly as its scope says**: a `read-only` token reads and cannot propose; a `write` token proposes and **cannot deliver (403)**; a `full` token of a maintainer **can** reach the delivery route's authorization; a token with `--repos` reaches only those repositories (a request for another repository answers as a hidden repository does: 404). Use real routes, real status codes.
  - (b) `token revoke` and a **disable** of the account each refuse the token on the very next request; an expired token (clock moved by the test) is refused; `token list` shows what happened to `last used` (and that reading twice within the hour writes once: the foundation's rule is not re-tested, only observed).
  - (c) **`--out`**: mode is 0600 (stat), the exclusive create refuses an existing file and a symlink, a directory that does not exist is refused with nothing stored, a failure after the file is written leaves no token stored (inject the failure) and the reverse order; the token read back from the file **works as a bearer** and is the **only** place the secret exists besides the one printed line (database dump, events, logs, `/proc/<pid>/cmdline` and `environ`: canary-checked; the printed token and the file's token are the same string).
  - (d) **Standard output is exactly one line** by default; standard error carries the explanation; with `--out` standard output carries the path sentence only.
  - (e) Refusals table (each: exit code, the English phrase, the Japanese by `--lang` and by `LC_ALL`, **stdout empty, every table dumped before and after equal**): no such account; disabled account; name empty/61 characters/control character; scope missing/unknown; `--expires-days` 0/366/not a number; `--repos` to a repository that does not exist, 21 repositories; the 201st unexpired token; `--out` existing/symlink/missing directory; `revoke` an unknown id and another account's id.
  - (f) **Beside a live server**: eight `token create` at once while the server answers; a held write lock gives the busy sentence, exit 5, nothing changed; a real 0.9.0 data directory (the foundation's migration fixture): `token list` shows the old tokens with the placeholder name and the commands work.
  - (g) **Mutations, each shown failing once and reverted:** the event detail containing the token; `--out` created with mode 0644 then chmod; `--out` overwriting; a token for a disabled account; `--expires-days` 366 accepted; `revoke` ignoring the holder; `--repos` ignored (a token that reaches everything); the token also written to standard error; the file left behind when the store fails.
**T6 — The documents (small).** `docs/client.md`'s "The token" section gains **two sentences** (an operator can make a token with `planeter operator token create … --out FILE` and give the path to `--token-file`; where a person has the pages of step 2 they make their own): **only if** it is true of this release and say what you changed. Nothing else in the docs (`docs/accounts.md` is a later handoff).

## Non-change scope
No page, no route, no API, no OpenAPI change, no self-service anything (step 2), no change to the foundation's tables or rules (a fix is reported, not silently made), no `authorize()` change, no provisioning, no issuer allowance, no new dependency, no `unsafe`. No sign-off record, baseline, `ja.signed` or `SignOff`. No tag, release or upload.

## Acceptance criteria
A token made by the command works at once and exactly as its scope and repositories say; it is shown once (one stdout line, or the 0600 file) and exists nowhere else but as its hash; revoke and disable refuse it at the next request; every refusal changes nothing; the canaries are clean; the commands run beside a live server; all gates green with tests with prikk 0.58.0 three times in a row **and a test file that needs prikk says so (the CI `build` job has none)**; CI green on all eight jobs; `tools/repeat-under-load.sh 20` on the new test file clean.

Commits (hash → what, by task, each compiling and passing the tests it touches); real transcripts of every command in English and Japanese with the server running (the token itself shown only in a transcript made for the purpose with a throw-away token, and said to be so); the refusals table with the dump equality; T5's results; the file-mode and failure-order tests; the canary results; the mutations (failing output, then clean); `--status` and the reading-order file; the gates in a clean worktree (fmt, floor, pin, clippy, tests with prikk 0.58.0 three times in a row and without, `cargo deny`, `cargo audit` on a fresh database, ENF-2, doc, msrv) with commands, exit codes, tool versions, the advisory-database HEAD and count; deviations and open questions (say plainly what you could not show).
