## Change scope

**T1 — The handle rule (D-2).** One pure function in `planeter-core` (beside `check_owner_handle`, which stays as it is for existing handles): `check_new_handle(handle, reserved) -> Result<(), HandleError>`: ASCII lowercase letters, digits, `-`, `_`, `.`; starts with a letter or digit; **1 to 39 characters**; no `..`, not ending in `.`; not reserved (the same reserved predicate); a closed `HandleError` with a stable `reason()` word each (as `NameError`). A second pure function `handle_key(handle) -> String` = the ASCII-lowercase form used for **case-insensitive uniqueness**. Tests: a table (valid; each invalid class; 39 and 40 characters; a reserved word in every case; a Unicode look-alike such as Cyrillic `а`; a trailing dot; `..`). **No rename function exists or is added.**

**T2 — The password rule with normalization (D-4).** In `planeter-auth`: `check_new_password(password, handle) -> Result<NormalizedPassword, PasswordError>`: **NFKC-normalize first** (`icu_normalizer`, already in the lock through `url`: add it as a **direct** dependency of `planeter-auth` with its record in `docs/dependency-policy.md`'s table of changes (crate count unchanged: show `cargo tree` before and after, and the licence), then count **Unicode scalar values**: at least 12 and at most 128; not equal to the handle (compared normalized and lowercased); **not in the embedded common-password list** (a data file in the repository, a few thousand entries from a licence-clean source **whose name, URL, licence and date you record in the file's header and in `docs/dependency-policy.md`**; compared after normalization and lowercasing; loaded at compile time with `include_str!`; bounded; **no network**). The closed `PasswordError` says which rule failed (`too_short`, `too_long`, `is_handle`, `too_common`). **Hash and verify the normalized form on both paths** (`authenticate_password` normalizes what it receives before verifying), so a password set through any input method verifies through any other; **for ASCII nothing changes, so every existing hash still verifies: show that with a test using a hash made by the pre-change code.** Also: **rehash on sign-in** when the stored hash's Argon2id parameters differ from the current ones (an upgrade path; the parameters are not changed in this handoff: say what they are and write the test with a deliberately weaker stored hash). Tests: composed and decomposed forms of the same Japanese password verify each other (`が` as U+304C and U+304B U+3099), a fullwidth Latin password equals its ASCII form under NFKC (and say that this is what NFKC does), 11/12/128/129 characters, an emoji counted as one, the handle rule, a common password in different cases, and that no error text contains the password. Mutation: normalization removed on the verify path only.

**T3 — The schema (idempotent, nothing existing touched).** With `add_column_if_missing` and `CREATE TABLE IF NOT EXISTS`, at start:
- `accounts`: `created_at` (integer, null for older rows), `disabled_at` (integer, null), `disabled_reason` (text, null, at most 200 characters, display-safe like a key event's detail), `password_changed_at` (integer, null).
- `tokens`: `id` (text: a random 16-character lowercase hex **public** identifier; **older rows get one assigned at start, once**, in one transaction), `name` (text; older rows `(created before 0.10.0)`), `created_at` (integer; older rows null), `last_used_at` (integer, null). A **unique index on `id`**. Nothing about the token's hash or secret changes; existing tokens keep working unchanged.
- **`account_events`** (D-7): `account` (the handle), `kind` (a closed set, a CHECK: `created`, `password_set`, `password_changed`, `identity_linked`, `identity_unlinked`, `token_created`, `token_revoked`, `session_ended`, `role_granted`, `role_revoked`, `disabled`, `enabled`, `signed_in_new_method`), `by` (`self|operator|provider`), `detail` (text, at most 200 characters, **display-safe, cut at a character boundary, never refused**), `at` (integer), an auto id. **No delete function exists.** Never a secret, a hash, a token or an address (a test over the whole table and the logs of a run with canaries).
- A trait `AccountEventStore` with `record`, `recent(account, limit)` (newest first, `limit` capped at 200) and `all(account)`, SQLite and in-memory forms, as `KeyEventStore`.
- The unique rule of D-2 held by the database: a **`handle_key` column with a unique index** on accounts (filled for every account at start; **if two existing accounts collide case-insensitively, the start does not fail and does not rename anyone: it records the collision (counts only) and the index is created `WHERE` the collision does not exist** — decide the exact SQLite form that makes this safe, show it works on a database with such a pair, and say what `planeter operator account list --check` (a later handoff) will report). Organizations' handles count too: a new account's `handle_key` must also not equal an existing organization's or user-owner's (`owner` of a repository) handle compared the same way. Tests on a real 0.9.0 data directory (upgrade), on a database with a collision, and a second start doing nothing.

**T4 — Disabled means refused, everywhere, at once (D-6).** `Account` gains `disabled: Option<DisabledState>`; `AccountStore` gains the reads and the write (`disable(handle, reason, at)`, `enable(handle)`; a write that also ends the account's sessions in the **same transaction**). Then: `authenticate_password`, `authenticate_oidc`, **`authenticate_token`** (it must look the account up: tokens of a disabled account are refused, **at each use**), **session resolution** (a session of a disabled account is no session) and every other path that builds a `Principal::User`/`MachineAsUser` (grep for them all and list them in the report) refuse a disabled account. Error shape: a password sign-in answers exactly as a wrong password does (**same response and the same time**, IS-31: extend the existing timing test with a disabled account); a token gets the same 401 as an unknown token. **Provider-verified sign-ins are told plainly:** `oidc_callback` for a verified identity whose linked account is disabled shows a new notice (English and Japanese, in the project's plain words, **one sentence with what to do**: "This account has been disabled. Ask the person who runs this server."); and for a verified identity with **no** account, the existing `SsoUnlinked` notice is checked for the same plainness and **reworded only if it is unclear** (say what you did and show both texts). Tests (real prikk is not needed; the real router): a live session and a token **refused on the very next request** after `disable`; `enable` restores a token (until its expiry); the disabled notice for a verified identity; a password attempt on a disabled account indistinguishable from a wrong password (status, body, and timing within the existing test's bound); mutation for each path (a path that forgets the check).

**T5 — The token record (D-8's data, no page).** `TokenRecord` gains `id`, `name`, `created_at`, `last_used_at`; `CredentialStore` gains `list_tokens(user)` (newest first, **bounded to 200**), `revoke_token(user, id)` (by id **and** user: a person's id never reaches another's token) and `touch_token(hash, now)` which writes `last_used_at` **at most once an hour per token** (compare before writing: reading must not be a write on every request; test with a counting store). `add_token` requires a name (1 to 60 characters, display-safe) and **an expiry no later than 365 days from now**; `mint_token` is unchanged. `authenticate_token` calls `touch_token` after a success. Tests: the once-an-hour rule, the bound of 200, revocation by the wrong user does nothing, an expired token refused, older tokens (no id before the migration) work and are listed with the placeholder name.

**T6 — The password and account writes the commands will call.** In `planeter-auth` (a small service, no command yet): `create_account(handle, display_name, password: Option<NormalizedPassword>)` (the handle rule, the case-insensitive uniqueness, the display name's length (at most 100 characters) and display-safety, writes `created`), `set_password` (ends the account's sessions; writes `password_set`), `link_oidc` / `unlink_oidc` (writes events; the issuer is whatever the caller passes: the command checks it is the configured one), all **one transaction each** and refusing with a closed error that changes nothing. Tests for each, including that a failed write leaves no event.

## Non-change scope
No `planeter operator` command, no page, no route, no OpenAPI change (the token and account APIs are step 2), no email use of any kind, no provisioning, no change to `authorize()`, to the creation flow or to the keys work, no change to the issuer guard (its own handoff). **No Japanese catalog text beyond the one disabled-account notice** (and the `SsoUnlinked` rewording only if you found it unclear): give the sheet's `--status` line and the reading list for the owner. No new dependency other than `icu_normalizer` as a direct dependency of a crate the tree already carries. No tag, release or upload.

## Acceptance criteria
Every control above has its test and its shown mutation; the migration works on a real 0.9.0 data directory and on a collision; existing passwords and tokens work unchanged; a disabled account is refused on every path listed; `cargo tree` shows the crate count unchanged; all gates green with tests with prikk 0.58.0 **three times in a row**; CI green on all eight jobs; `tools/repeat-under-load.sh 20` on the new test files clean.

Commits (hash → what, by task T1–T6, **each commit compiling and passing the tests it touches**); the list of every path that builds a principal; the migration transcripts (before/after table lists and counts, the collision case); the dependency-policy rows (the crate, the password list's source and licence); the timing evidence for IS-31; the mutations (failing output, then clean); `planeter-i18n-sheet --status` and the notice texts; the gates in a clean worktree (fmt, floor, pin, clippy, tests with prikk 0.58.0 three times in a row and without, `cargo deny`, `cargo audit` on a fresh database, ENF-2, doc, msrv) with commands, exit codes, tool versions, the advisory-database HEAD and count; deviations and open questions (say plainly what you could not show).
