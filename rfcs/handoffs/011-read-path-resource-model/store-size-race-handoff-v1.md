# RFC 011 / IS-74 — A read must not be refused because a file vanished while the store was being measured — Fix Handoff (v1)

| | |
|---|---|
| Document | **A product defect, found because CI now runs the real-prikk tests** (`ci-prikk-review-request.md`): `crates/planeter-web/tests/transport_fetch.rs::reads_succeed_while_an_export_runs_and_a_slow_client_holds_no_lease` failed on the runner in 2 of 8 runs with `planeter: a read was not admitted: the repository store could not be measured: No such file or directory (os error 2)` and a **503 on `GET …/history`**. Every read is admitted by `planeter_core::admission::store_size_limited`, which walks `<repo>/.prikk` (`read_dir`, then `symlink_metadata` of each entry) and **returns an error for any failure** ("any failure is an error, never a guess"). A file that prikk creates and removes **between the listing and the stat** gives `ENOENT`, and the read is refused. **That is the running service**: in production a read (a page, `log`, a clone) that arrives while a write is in progress (an accept, an import, a delivery, prikk's own temporary files) can be answered `503 unavailable` for no reason that is the reader's or the operator's. The measurement would have counted that file as nothing if it had been listed a moment later; refusing the read is the wrong answer. It is in 0.9.0 as released. **This is not a security defect** (a transient availability one, in the safe direction) and **it is not the development-machine matter of RFC 010 Amendment 1**: it is the server's own behaviour. |
| Status | Assigned 2026-11-27 (SCHEDULE D-146). **First in the queue**: CI's `build` job is red about one run in four until it is fixed. |
| Basis | `crates/planeter-core/src/admission.rs` (`store_size`, `store_size_limited`, `StoreSizeError`, `MAX_STORE_ENTRIES`, and every caller: `grep -rn "store_size" crates`), RFC 011 (the read-path resource model: why the store is measured at all: the cost of a read is a function of its size), `ci-prikk-review-request.md` ("The flake, and why CI is not yet green three times in a row"). |
| Audience | Dev team. Return a review-request package. |

## Change scope
1. **Treat a vanished entry as nothing, and nothing else as nothing.** In `store_size_limited`: `ErrorKind::NotFound` from `symlink_metadata` of an entry **and** from `read_dir` of a **sub**directory (a directory that was listed and is gone) means "gone since the listing": add nothing, push nothing, count the entry as seen (the entry bound still counts it). **Every other error stays an error** (permission denied, I/O error, a path that is not a directory where one was listed, too many entries), and **a missing `.prikk` itself (the first `read_dir`, the root) stays an error**: a repository whose store is not there is not a repository to read. Update the function's comment: "any failure is an error, never a guess, **except that an entry that disappears between being listed and being looked at has size zero: it is gone**." Keep the bound (`MAX_STORE_ENTRIES`) and the symlink rule exactly as they are (a symbolic link is not followed, as now).
2. **A deterministic test, not a stress test.** Add a test seam so that a file can be removed **between** the listing and the stat (a `#[cfg(test)]` hook in `store_size_limited`, or a small internal function that takes a closure called between the two steps; no new public API, no `unsafe`, no dependency): (a) a directory with files whose entry is removed in the hook → `Ok` and the size of what is left; (b) a **subdirectory** removed after it was pushed on the stack → `Ok`; (c) the same with a *file* replaced by a *directory* of the same name between the steps (the stat sees what is there now: it must not panic or loop); (d) `PermissionDenied` (a directory with no read permission in the test's own temp tree) → still `Err(Io)`; (e) a missing `.prikk` → still `Err`; (f) the entry bound still returns `TooManyEntries` when vanished entries are counted. **Mutation:** the `NotFound` arm removed → (a) and (b) fail.
3. **A test through the service** (the existing `transport_fetch.rs` test is the reproduction on a runner; do not rely on it): a read admitted while a **writer thread** creates and removes files under `<repo>/.prikk` in a tight loop, 2,000 reads, **0 refused**; before the fix it refuses some (show the count on the old code on this machine; if it cannot be reproduced here, say so and say how many iterations you tried: the deterministic tests of item 2 are the proof).
4. **CI:** after the fix, the `build` job on **three consecutive runs** is green (this is the acceptance criterion `ci-prikk-handoff-v1` could not meet): report the run ids. If `reads_succeed_while_an_export_runs_and_a_slow_client_holds_no_lease` still fails on the runner, report the new message and stop (do not skip it).
5. **Say in the report** whether any other function walks `.prikk` (or another tree prikk writes in) and returns an error for a file that can vanish (`grep` for `read_dir`/`symlink_metadata`/`metadata` over `crates/*/src` with a note per hit: a vanishing file between two calls on the same path): list them with a decision; fix only `store_size_limited` here, report the others for the architect.

## Non-change scope
No other behaviour of admission (the budgets, the pools, the limits), no change to what a read costs or to any threshold, no catalog text, no new dependency or `unsafe`, no change to prikk's use, no change to the CI workflow in this handoff beyond reporting the runs, no sign-off record, baseline, `ja.signed` or `SignOff`, no tag, release or upload.

## Acceptance criteria
A vanished entry is counted as nothing and every other failure still refuses; the deterministic tests (a to f) and the mutation; the writer-thread test; the `build` job green on three consecutive CI runs; `tools/gates.sh --tier review` green on the commit; the list of other walkers.

## Required evidence
Commits (hash → what, each compiling and passing the tests it touches); the changed function and its comment; the test names and outputs; the mutation; the writer-thread result before and after; the three CI run ids; the walkers table; the review-tier table; deviations and open questions.
