## Why this is in scope, and why `store_signature_limited` is not

A file prikk creates and removes while it writes is nothing a reader did, and nothing an operator can act on. Today `files_digest` fails with it (`entry.metadata()?`, the nested `read_dir(dir)?`), so **an archive export or a changes page can be refused for a file the next walk would not show**; the failure is `Reason::Failed` / an export error, not a security matter and in the safe direction, but it is the same availability defect, in two more reads.

**`store_signature_limited` stays strict, and I agree with the reasoning in the review request**: its equal signatures are *positive evidence that the store did not change*; a file that vanished mid-walk **is** a change; an error there makes the caller treat the store as possibly changed. Do not touch it. Say so in a comment beside it (one sentence: why it is strict where the size walk and the digest walk are not), so the next reader does not "fix" it by symmetry.

## Change scope

1. **`files_digest`: an entry listed and gone is not in the digest; everything else stays an error.** `NotFound` from `entry.metadata()` of a listed entry → skip it. `NotFound` from the `read_dir` of a **sub**directory that was listed and is gone → skip it (what was listed before is in). Every other failure stays `Err`, and so does a missing `.prikk` itself (the root is not a subdirectory). Why this is right for a cache key, to be said in the function's comment: the digest is of what was there; a vanished file is a change, and the next walk that does not show it gives the same digest as this one, a walk that still shows its siblings' changed times gives another; **no walk can give an equal digest for a store whose files differ**, which is the only property a cache key needs. (If you find a case where that is not true, stop and tell me; that would make this a different change.)
2. **`artifacts.rs` `scan`**: the same two arms (`obj.metadata()?` and the shard listing). A scan runs for a listing and for recovery (`:339`, `:556`); recovery must not fail for an object that was renamed to `trash/` between the listing and the stat. Same rule, same exceptions.
3. **One rule, said once.** Three walks now have the same two arms. Decide, and say why in the report: either (a) three local `match`es of three lines each, or (b) one small `pub(crate)`/`pub` helper in `planeter-core` (`fn vanished(e: &io::Error) -> bool`, or a tolerant `read_dir` wrapper) used by all three. **My preference is (a) unless (b) makes the code smaller and adds nothing public that is not already public**; a new public item for three call sites that differ in what they do on a vanished entry is surface for its own sake. Whichever you choose, no change to `store_size_limited`'s behaviour, no re-test of what `796160e` proved.
4. **Deterministic tests, the same shape as `walk_tests`**, for each of the two walks (a test seam as a generic parameter of a private function, as `796160e` did; no `#[cfg(test)]` branch in production code): (a) a file removed between the listing and the stat → the digest / scan equals the one of what is left; (b) a subdirectory removed after it was listed → same; (c) a directory that cannot be read (mode 000; skips, saying so, where the user can read it anyway) → still `Err`; (d) a missing `.prikk` → still `Err`; (e) for `files_digest` only: **the digest of the store with the vanished file equals the digest taken afterwards of the same store**, and **differs from the digest of the store while the file was there** (the property in item 1, shown, not argued). **Mutation**: the `NotFound` arms removed → the (a) and (b) tests fail; report which fail.
5. **One test through the service for the export or the changes page**, in the shape of the writer-thread test of `796160e`: a writer creates and removes files under a stand-in `.prikk` while N requests go through the router; report **before and after** the number refused (it reproduces on the old code on this machine, as the first one did; if it does not for these two paths, say so and keep the deterministic tests as the proof). Skip, saying so, where it cannot run, as the other does.
6. **Write down what is left.** List again, in the report, the hits of `grep -rnE "read_dir|symlink_metadata|\.metadata\(\)|fs::metadata" crates/*/src` that still return an error for an entry that can vanish, with the reason each stays (the table of `store-size-race-review-request.md` is the base; update it, do not repeat it).

## Non-change scope
No change to `store_size_limited`, `store_signature_limited`'s behaviour, any threshold or budget, the export format, the cache key's **format** (the digest of an unchanged store must be byte-identical before and after this change: show it with one fixed store), no catalog text, no dependency, no `unsafe`, no CI workflow change.

## Acceptance criteria
Items 1–2 behave as written; the digest of a store that does not change during the walk is byte-identical to the one the old code gave; the deterministic tests and the mutation; the service test with before/after; `store_signature_limited` unchanged apart from its comment; clippy `-D warnings` and `cargo fmt --check` with the pinned compiler; CI green on the head (one run is enough here; the flake that needed five attempts was a different test).

## Required evidence
Commits (hash → what, each compiling); the changed functions and their comments; the test names and outputs; the mutation; the before/after of the service test; the byte-identity check; the updated walker table; the review-tier table (`tools/gates.sh --tier review`, the snapshot form); deviations and open questions.
