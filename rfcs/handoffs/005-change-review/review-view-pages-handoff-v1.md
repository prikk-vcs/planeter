## T0 — a bound on waiters (finding of the engine review)
The single-flight parks one blocking-pool thread per waiting request (engine request, deviation 5). Bound it: at most **8 waiters per key**; the ninth request is answered `changes_unavailable` / `busy` (503, `Retry-After`) at once, without parking. Test with 20 simultaneous identical requests (8 wait, the rest are busy, one extraction), and a mutation that removes the bound. Count it in the existing `busy` counter.

## The pages (routes beside the proposal's; same authorization class as the proposal page; the IS-14 table lists them)
1. **The link.** On the proposal page, each revision gets a link whose text is unique and says what it does: English "See the changes in revision {seq}" (Japanese: written by you in plain Japanese). The current revision's link is also placed beside the revision heading. The old "file-by-file view is not available yet" sentence and its catalog key go away (the key is removed from both catalogs; check that nothing else uses it).
2. **`GET /{owner}/{name}/proposals/{id}/revisions/{seq}/changes[?after=]` — the changes page.** One `<h1>`: "Changes in revision {seq} of proposal #{id}" (the title of the proposal is on the page already; do not repeat it as another heading). Then, in this order: (a) a short block of plain statements (below); (b) a summary line "{n} files changed, {a} lines added, {r} lines removed" with correct plural forms in both languages, and, if some files are not shown, "{k} of them cannot be shown as text (see the Notes column)"; (c) **a table** — caption "Files changed in revision {seq}", header cells, one row per file: *File* (the display path in `<code>`, a link "{path}" to its file page when `shown`; plain text otherwise), *Change* (words: Added / Changed / Deleted / Type changed — never colour alone), *Lines* ("+{a} −{r}" as text with the words "added"/"removed" available to assistive technology, e.g. visually hidden), *Notes* (the reason a diff is not shown, one plain sentence per reason of the closed list: too large, not UTF-8 text, binary, symbolic link, directory, unreadable); (d) previous/next links when paged (text "Earlier files" / "More files"), 100 per page; (e) a link back to the proposal and one to download the revision (the existing artifact download, if the caller may use it). Empty change set: "This revision changes no files." (a revision can be an empty commit).
3. **`GET …/revisions/{seq}/changes/{file_id}` — the file page.** `<h1>`: the display path (in `<code>`) — if `path_escaped`, a sentence says the name contains characters that are shown as escapes. Then the status in words; the diff as **one table** with caption "Changes to {path}", columns *Old line*, *New line*, *Change*, *Text*; **hunk headers as rows** in words ("Lines {a}–{b} before, lines {c}–{d} after"); each row's *Change* cell carries a visible "+" / "−" / blank and a visually hidden word ("Added line", "Removed line", "Unchanged line"); line text in `<code>` (preserving spaces: `white-space: pre-wrap`; long lines wrap — `overflow-wrap: anywhere` — so **nothing scrolls sideways at 320 CSS px**); the truncation sentences of the engine (`truncated`, `approximate`, cut lines) in words under the table. A symbolic link: "This is a symbolic link to {target}" (target escaped, never a link). A file not shown: its reason, a sentence, and the way out ("Download revision {seq} to read it" when permitted). Links: back to the list, previous/next changed file in list order.
4. **The statements (exact English; Japanese by you, plain, flagged for the owner).**
   - always: "These files are rebuilt from the patches in this revision. Nothing here is signed."
   - when `provisional`: "No earlier check of this repository's history was available, so the files were rebuilt by replaying the history from the start. They match the patches; the history itself has not been checked."
   - when `base_differs`: "This revision says it was built on {declared}, but its first patch continues from {real}. The changes below are compared with {real}."
   - when there is no earlier file (`before_block` null): "This revision starts the history, so there are no earlier files to compare with."
   - `compared`: "Compared with {before} (the block the first patch continues from)." — the block id as a short form in `<code>` (first 12 hex) with the full id in the `title`-free way the other pages use (a `<details>`/text, not a tooltip).
5. **Every unavailable reason** (`claim_not_held`, `not_one_change`, `tree_too_large`, `busy`, `timed_out`, `failed`) is a plain page in the project's one style for plain pages (a heading, one or two sentences that say **what happened and what to do next**, a link back), with the engine's HTTP status; `busy`/`timed_out` say it is worth trying again in a moment; `tree_too_large` and `claim_not_held` say what the person can do instead (download the revision; for `claim_not_held`: "The work of this revision is no longer held here as a proposal, for example because it arrived as signed history. Look at the repository's history instead."). No reason mentions an internal term (claim, chain, extract, foot) in the English or the Japanese; the closed English list is yours to write, **the architect reads it in the review**.
6. **No JavaScript, no inline style** (the existing rule); no new third-party asset; no syntax highlighting; no colour carries meaning alone.

## Accessibility and inclusion (tested, not claimed)
- Add the new pages and **every reason page** to the structural checker's states (`tests/structure/`), in both languages and both with a stand-in and a real prikk where that file does it today: the checks (one `<h1>`, landmarks, skip link, table captions and header cells, unique titles, link text not vague, language/direction) must pass over them, and the new link text must not be on the vague list.
- Stylesheet (`tests/stylesheet.rs`): the diff colours are **supplementary**: added/removed rows have a text marker in the cell and a border or underline style visible in forced-colors mode; contrast ≥ 4.5:1 for text on the row backgrounds in the light and the dark theme (add the pairs to the tested list); logical properties only; no `outline: none`; targets ≥ 24 × 24 CSS px; `pre-wrap`/`overflow-wrap` rules present.
- **A browser measurement, once, not in CI** (as 2026-10-23): headless Chromium over the new pages in both languages and both themes at 320 and 1280 CSS px, with and without the WCAG 1.4.12 text-spacing override: no sideways scroll, no target under 24 px, focus visible on every link. Keep the script out of the build; report the table; note the browsers and assistive technologies **not** tried (all of them: say so in `docs/accessibility.md`, "What we have not checked": the diff table with a screen reader is the first thing to try).
- Plain words: use the glossary terms (*proposal*, *revision*, *patch*); nothing technical in a sentence a reviewer reads (`plain_words.rs`, `glossary*.rs` pass); the retired-words list stays clean.
- Japanese: plain, consistent with `docs/glossary/ja.md` (変更 as a noun only for the fixed pairs; use 変わる for the verb; ログイン; リビジョン; 提案; パッチ; spaces around numerals with counters; full-width brackets); **do not use 保持 or 預かる in new text** (the owner finds 保持 strange in some sentences and 預かる unnatural in others; say "ここにあります"/"このサーバーにあります" or restructure). They ship flagged "new since sign-off" and the owner reads them before the release; do not touch the sign-off data or the baselines.

## Safety (hostile content reaches a page here)
Every name and every line of text passes through the engine's display function **and** the template's escaping (double safety, not either/or): tests render a file named `<script>alert(1)</script>.txt`, a line `<img src=x onerror=alert(1)>`, a name with a bidi override and a line with U+202E, a 2,000+ character line, a symbolic link target `javascript:alert(1)`, and assert the page contains none of them unescaped and no active link comes from file content. The sanitizer is **not** used on diff text (it is text, not HTML). Headers as the other dynamic pages (`private, no-cache`, `Vary` including `Accept-Language`, `Content-Language`, the CSP). The rate limit of the proposal routes applies.

## Tests
`pages_in_two_languages` and `language_switching` cover the new pages; `route_enumeration` lists the routes; an end-to-end test with the real client/prikk/server (as `changes_e2e`) renders the changes page and one file page in English and Japanese and checks the statements, the table headers and the plural forms (1 file / 2 files; 0 lines; 1 line); the reason pages are rendered for each reason (the e2e already produces each); the T0 test; a mutation for each of: the hostile-escape test, the `provisional` statement, the "Change" words, the vague-link rule (a link text "here" must fail), the sideways-scroll rule.

## Non-change scope
No engine change except T0; no new setting; no JSON change except what T0 needs; no line comments; no syntax highlighting; no side-by-side view; no "changes since revision N"; no rename labelling; no signature display; no change to the proposal page's other content; no sign-off data; no version change; no floor change.

## Acceptance criteria
The pages and statements as above; all structural, stylesheet, glossary, plain-words and language-rule tests green with the new states; the browser measurement table; the sheet regenerated and `--check` passing (report the count of messages to read and the fingerprint); all gates green with prikk 0.57.0 and without (deny/audit 0 with the pinned tools; the publish dry run with a **fresh `CARGO_TARGET_DIR`**), CI green.

## Required evidence and review-request format
Commits (hash → what, T0 first); the English texts of every new message in one table (key → text); screenshots are not needed — instead the HTML of the changes page, a file page and one reason page, saved as files in the logs, in both languages; the test table (case → mutation → result); the browser measurement; the sheet header and fingerprint; every gate with command, exit code, tool versions and advisory-database HEAD; deviations and open questions.
