## T2 — `verify`: the new count line and array

Teach the strict reader (`planeter-prikk`) the line and the array (unknown *fields* are tolerated by design; an unknown *line* in the text report must not break `verify`'s parse). ## T3 — The `extract` driver

In `planeter-prikk` (read-class verb, lease class **R**, RFC 004 D-7):
(a) `extract(point, destination, options)` where `point` is `Ref(name)`, `Block(id)` or `Claim(id)`; options `plan_only`, `max_bytes`, `max_files`, `allow_full_replay`. It runs `prikk extract (--ref|--claim) … <dir> --format json [--plan-only] [--max-bytes N] [--max-files N] [--allow-full-replay]` in the sandbox.
(b) **Strict readers** for `extract-report-v1` (`point`, `point_kind`, `target_block_id`, `claim_parent_block_id` (nullable), `provisional`, `written`, `file_count`, `total_bytes`, `largest_file_bytes`, `extract_repository`) and `refusal-v1` (`command`, `refusal`, `reason` (nullable), `message`). **All 13 refusal ids** are a closed enum with a catch-all `Other(String)` that is a *named, logged* case, never silently mapped; the `reason` values `signer-not-adopted`, `not-recorded`, `no-checkpoint` are a closed enum likewise. Obtain the 13 ids from prikk's own documentation/`--help`/source if available to you, otherwise by provoking each one with a real repository (list which you provoked and which you took from the letter or docs; do not invent any). A refusal on stdout is parsed even though the exit code is 1; a non-JSON failure (crash, timeout, ceiling) is a `PrikkError` as for every other verb.
(c) **The destination is ours to make safe**, because 0.54 does not refuse a destination inside the repository: the driver allocates the destination itself as **a fresh, not-yet-existing path under a per-call working directory outside every repository** (the pattern of the export working directory in part 3a T0b / the propose accept: `<artifact dir or spool>/work/<id>/out/tree`, mounted read-write and **only** that directory), refuses (a named driver error, before any prikk call) a destination that resolves inside the repository root or inside a symlink to it, and removes the working directory with everything in it when the guard is dropped. A test shows the refusal and shows that a destination inside the repository is never passed to prikk (a stand-in prikk that records its argv).
(d) The extracted tree is **untrusted data**: the driver returns a handle (path + report) and never reads files itself in this part; any later reader must treat names and contents as hostile (note this in the doc comment and in `docs/`). Add a test that a stand-in "extraction" containing a symlink pointing outside is reported to the caller as a symlink and is not followed by anything the driver does (the driver does not walk the tree).
(e) `claim_parent_block_id`: carried through; `None` means the point is not a claim. Do **not** build the "declared base disagrees" refusal here (RFC 005 part 6).
(f) `refusal-v1` `damaged-repository` from `--claim` **in 0.54.x is also what prikk says for a claim whose parent is still pending** (prikk's letter, §3; the repository is not damaged; 0.55.0 will give it its own id). The driver must **not** report damage for it: for `Claim` points, map `damaged-repository` to a distinct `ClaimParentNotSealedOrDamaged` outcome whose text says both possibilities, and add the ledger reference in the doc comment. A test with a real pending claim (a proposal accepted by `propose` whose parent is not sealed) reproduces it and pins the mapping (if the 0.54.1 behaviour differs from the letter, report the facts; do not guess).

## T4 — Measure the cost of `extract` (RFC 011: per prikk release)

On real prikk 0.54.1, in your own scratch area (not CI): the peak **data segment (`VmData`, what the ceiling limits, sampled maximum as in part 4b) and resident set** and wall time of `extract` for: a tree of 1,000 × 10 KiB files; 100 × 1 MiB; **one file of 1, 16, 64, 128 MiB** (prikk's team measured ≈ 137 MiB peak for 64 MiB); a deep history (a point 60 blocks beyond the nearest admitted checkpoint, `--allow-full-replay`); a `--claim` point; and `--plan-only` for each (prikk says it costs the same as a real write); on an empty store and on one with 5,000 pending patches. Fit `cost ≈ a + b × largest_file_bytes + c × total_bytes + d × file_count`, report the worst ratio per shape, and propose the **`ReadVerb::Extract` cost rule** (`CostRule`), its floor and its ceiling (×1.5 as for the other verbs unless the numbers say otherwise). Implement the rule in `admission.rs` with its provenance and update `MEASURED_ON`; keep the per-verb table's tests style (one measured row per shape, `cost ≥ held`). Extract is **heavy-pool** unless the numbers put it under the light-class maximum. The admission is also given the `largest_file_bytes` from a **`--plan-only` pre-call** only if the numbers show the plan is much cheaper than a write; otherwise the rule uses the configured `--max-bytes` bound (state which you chose and why).
Set the **default bounds** for extraction in one place: `--max-bytes` (propose **64 MiB** total, configurable) and `--max-files` (propose **10,000**), documented; a point over either is the prikk refusal, reported as a plain "too large to compare here" outcome (the catalog text comes with the review UI, not now).

## Non-change scope

## Acceptance criteria

The floor agrees in all three places (floor check exit 0) and the suite passes on 0.54.1 **and fails with a clear start-up refusal on 0.53.0** (a test with a stand-in `prikk --version`); T2's cases; T3's tests (every provoked refusal id parses to its enum value; unknown id → `Other` and a log line; the destination rules; the damaged/pending mapping; the symlink test); T4's table, fit, rule and tests, mutation (lowering the rule's `b` is caught); all earlier checks (IS-14 table, OpenAPI drift guard, ENF-2) pass; every gate green including both supply-chain gates (fresh advisory database), both test runs named, `cargo doc`.

## Prohibited shortcuts

No guessed refusal id; no mapping of an unknown id to a known one; no destination inside a repository ever passed to prikk; no reading of the extracted tree; no constant in the cost rule without a measurement; no claim that a case was run that was not; no hard-coded user-visible text.

## Required evidence and review-request format

Commits (hash → what, by task; the floor commit first); the list of the 13 refusal ids with, for each, how it was obtained (provoked / documented / letter); the T4 table, fit, worst ratios, the rule and its provenance, the scripts' location; the transcripts of the destination, symlink and pending-claim tests; every gate with command and exit code and the advisory-database HEAD; deviations and open questions.
