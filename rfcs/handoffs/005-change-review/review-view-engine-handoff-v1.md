## What the engine produces (the contract; the architect's decisions)

**For one revision of one proposal:** a **change set** — what the revision does to the files, compared with the revision's own base.

- **The points.** From the revision's `claim_ids`, read the pending claims (`sync pending --format json`) and build the **chain** inside this revision: the **foot** is the claim whose target block is not a parent of another claim of the revision; the **root** is the claim whose parent is not the target of another. *Exactly one chain* is supported; several heads or an unconnected set is answered `not_one_change` (in words, see Errors), never guessed. The **after** tree is `extract --claim <foot>`. The **before** tree is the root claim's `claim_parent_block_id`: `extract --ref <that block>`; if the root has no parent (the proposal starts a history), the before tree is **empty** and the page will say "no earlier files". A revision whose declared base (`declared_base`) differs from the real parent is **compared with the real parent** and flagged (`base_differs: true`, with both ids), never silently reconciled.
- **The comparison is made by planeter**, over two directories it never trusts: for every path in either tree, decide `added`, `deleted`, `modified`, `type_changed` (file ↔ symbolic link ↔ directory), or unchanged (dropped). A file moved to a new name is a deletion plus an addition in this release (no rename labelling: cut-first in the scope); do not guess at renames.
- **A file entry** has: `file_id` (the SHA-256 hex of the exact path bytes: this, never the path, goes into URLs), `path` (display-safe, below), `path_escaped` (true if the display differs from the bytes), `status`, `kind` (`text`, `binary`, `symlink`, `directory`), `size_before`, `size_after`, and for text: `lines_added`, `lines_removed`, `shown` (true if a diff is available) and, if not, `not_shown_because` ∈ {`too_large`, `not_utf8`, `binary`, `symlink`, `directory`, `unreadable`} — a closed list, each with a plain sentence in the catalog (handoff 2). A symbolic link shows its **target as text** and is never followed; a directory entry is listed only when it appears or disappears with no files (rare); special files (pipe, device, socket) are `unreadable` and never opened.
- **Display-safe paths and text.** Paths are bytes. The display form: valid UTF-8 kept; anything else shown as `\xNN` per byte; C0/C1 controls, DEL, line and paragraph separators, **bidirectional controls (U+202A–202E, U+2066–2069, U+200E/F, U+061C)** and zero-width/format characters (U+200B–200D, U+2060, U+FEFF) shown as visible `\u{…}` escapes; a name longer than 1,024 bytes is cut with an explicit "…(N more bytes)". The same escaping applies to every line of diff text and to a symbolic link's target, **except** tab (kept) and the line terminator; a stray CR in a line is shown as `␍` (U+240D). A line is cut for display at 2,000 characters with an explicit "…(N more characters)" marker. These rules live in one function with its own tests.
- **A text diff** exists only when both sides (or the one side that exists) are valid UTF-8 text, each side ≤ **256 KiB**, and contain no NUL byte. Otherwise `not_shown_because`. Lines split on `\n`. Hunks with **3 lines of context**; at most **5,000 diff lines** are returned per file (`truncated: {lines_not_shown}` says how many remain). The algorithm is bounded: a hard cap on the edit distance explored; when it is exceeded, return the whole-file replacement (all old lines removed, all new added, still subject to the 5,000-line cap) and say `approximate: true`, never an unbounded computation.
- **Totals and limits.** The list is ordered by display path and paged (`after=<file_id>`, `limit` ≤ 200, default 100); the response carries `files_changed`, `lines_added`, `lines_removed` (totals over text files that are `shown`), `unshown` (count of files with a reason), and the effective limits. At most **10,000 changed files** are listed (the extract bound `DEFAULT_MAX_FILES`); beyond it the whole view is `tree_too_large`.
- **Honesty fields.** `compared: {before_block, after_block, base_differs, declared_base}` and `rebuilt: true` (always: the files are rebuilt by prikk from the patches), `provisional` copied from the extract report (true = no checkpoint verified by the repository itself was in reach), `chain_signature` copied from the report. Pages will say, in words, that the files are rebuilt from the proposal's patches and that nothing here is signed; they will **not** display signature outcomes in this release.

## Resource and safety rules
- **Cost and admission.** Use the existing `extract` admission (RFC 011): the view takes the heavy pool like any `extract`, with the existing default bound (`--max-bytes` 64 MiB, `--max-files` 10,000) and **no new setting**. A repository whose tree is over the bound gets `tree_too_large` (the page will say to download the revision and look at it locally). Two extractions per view (before and after) are made **one after the other**, never concurrently; the admission token is held for both. Busy → the existing `503 unavailable` with `Retry-After`, in words.
- **Cache.** The change set is a pure function of (foot claim id, root parent block id); both are content-addressed, so a cache entry is correct forever. Store the computed list and, lazily, each file's diff, in the spool (`PLANETER_SPOOL_DIR`, LRU, disposable; without a spool directory: compute per request, no cache, and say so in the start-up line). **Single-flight**: concurrent requests for the same key share one computation. Never cache an error that could be transient (busy, killed); cache `not_one_change`/`tree_too_large` for the key.
- **Walking the trees.** Never follow a link, never open anything but a regular file after `lstat` says it is one, depth cap 64, entry cap = the extract file bound, read a file only up to the size caps above (a larger one is compared by streamed content hash, not loaded). Everything is removed when the guard drops (the `ExtractWorkdir` rule). No `unsafe`.
- **Time.** The whole computation has a wall-time bound of 30 s (diff work off the async workers, `spawn_blocking`); exceeded → `unavailable`, nothing cached.
- **Authorization.** Same as reading the proposal (the read class that `GET …/proposals/{id}` uses); a hidden repository or an unknown proposal/revision answers 404 byte for byte like any other (IS-14/ENF-4: the new routes are in the enumerated table and probed).
- **Counters and logs.** One counter per outcome (`ok`, `not_one_change`, `tree_too_large`, `busy`, `timeout`, `claim_not_held`, `failed`) in the existing retention-sweep style summary or the metrics place that already exists for proposals; no file name or content in any log line.

## The JSON API (OpenAPI document updated, English and Japanese error messages through the catalog)
- `GET /api/v1/repos/{owner}/{name}/proposals/{id}/revisions/{seq}/changes[?after=&limit=]` → `{revision, compared, rebuilt, provisional, chain_signature, totals, limits, files:[…], next}`.
- `GET …/revisions/{seq}/changes/{file_id}` → the file entry plus `hunks:[{old_start,old_lines,new_start,new_lines,lines:[{op:"context"|"add"|"remove", text}]}]`, `truncated`, `approximate`.
- Errors in the project's one shape `{code, message, hint}`: `changes_unavailable` with a closed `reason` ∈ {`claim_not_held` (the revision's work is no longer pending here, e.g. it arrived in a received history), `not_one_change`, `tree_too_large`, `busy`, `timed_out`, `failed`}; plus the existing 404 for unknown/hidden. Add the new messages and hints to **both** catalogs through the usual route (English as you write it; the Japanese rows are written as plain Japanese by the dev team and will be flagged "new since sign-off" until the owner reads them; do not touch the sign-off data).

## Dependency (decided by rule, measured by you)
The text diff needs an algorithm. **Adopt `similar` if** it adds at most 2 crates to `Cargo.lock`, its licence is already on the allow-list (Apache-2.0/MIT), `cargo deny`/`audit` stay at 0 with no ignore, and it meets the worst-case test below; otherwise write a bounded Myers diff in `planeter-transport` (no dependency). Report the measurement per dependency-policy rule 1 ("N → M crates (+K); deny: …; audit: …; new licenses: …") **before** the commit that adopts it, as its own commit. Worst-case test (either choice): two 256 KiB files of 8,000 lines each with no common line, and two with every other line changed, finishing within the edit-distance cap and well inside the 30 s bound (report the times).

## Tests (each hostile case with a **mutation** that makes it fail, shown once)
Trees built by hand in a temp directory for the comparison unit tests, and a real-prikk end-to-end test (real client → real server → real prikk 0.57.0, as `client_e2e`/`transport_propose` do) for: a one-claim revision; a three-claim chain; an edit, a delete, an add, a rename (shown as delete + add), a mode/type change (file → symlink); a binary file; a 300 KiB text file; a Shift_JIS text file (`not_utf8`); a file whose name contains a newline, a bidirectional override, an invalid UTF-8 byte and `<script>`; a symlink to `/etc/passwd` and to a FIFO (never opened, the call returns); a symlink loop; a 100-level directory; 10,001 files; a one-line 5 MB text file; a file of 6,000 changed lines (cap); CRLF files; a revision whose work arrived as received sealed history (`claim_not_held`); a revision with two heads (`not_one_change`); a proposal with `base: none`; a revision whose declared base differs; a hidden repository and an unknown revision (same 404 bytes as the others); two concurrent identical requests (one extraction, counted); a second request served from the cache; the busy path; the cache not written for a transient error; no file name or content appears in the captured log of any run.
Also: the IS-14 route table lists the two new routes; the OpenAPI test passes; `forbid(unsafe_code)` holds; the boundary check passes; the new messages exist in both catalogs (the English-only/missing tests); the sheet regenerates (`planeter-i18n-sheet --lang ja --check`) and reports the new Japanese messages as "new since sign-off".

## Non-change scope
No page (handoff 2); no merge, no landing change, no change to `assurance`, `still_pending` or sightings; no line comments; no syntax highlighting; no "changes since revision N"; no rename labelling; no signature display; no new setting; no version change; no change to the floor.

## Acceptance criteria
The contract above, with every test and mutation; the dependency measurement as its own commit; all gates green with prikk 0.57.0 and without (the real-prikk tests skip with a reason when prikk is absent), `cargo deny`/`cargo audit` 0 with no ignore, ENF-2, doc, floor, pin, clippy, fmt, CI green; the threat-model input in the review request (what the surface accepts, what it can cost, what it refuses: a half page; the architect writes it into the threat model).

## Required evidence and review-request format
Commits (hash → what, the dependency measurement first); the contract's examples as real JSON from a real run (one list, one diff, one of each error); the test table (case → what it proves → mutation → result); timings of the worst-case test and of a typical view (cold and cached) on a 1,000-file repository; every gate with command, exit code, prikk version and advisory-database HEAD; deviations and open questions.
